## Phase 0 — ✅ ปิดแล้ว 2026-08-04 เย็น (เหลือ 1 ข้อรอเจ้าของ)

**แก้ความเข้าใจผิดของผมก่อน 3 ข้อ — เจ้าของทักมา:**

### ข. เรื่องการ์ด SD ไม่ใช่คำถามถึง CIB — เป็นเรื่องฝั่งเรา

ที่ผมร่างจดหมายถาม CIB เรื่องการ์ดไม่ฟอร์แมต 25 ใบ **ผิดที่** — ฮาร์ดแวร์ในกล้องเป็นเรื่องของเรา/ผู้ติดตั้ง ไม่ใช่ของ CIB
คำถามที่ถูกต้องคือสิ่งที่เจ้าของสั่งให้ตรวจ: **กล้องมี ANR ไหม**

**ผลตรวจ ANR (Automatic Network Replenishment):**

```
/ISAPI/ContentMgmt/record/tracks/101  →  ไม่มีฟิลด์ ANR เลย (ตรวจ 4 ตัว)
```

รวมกับผลสำรวจการ์ดก่อนหน้า — **สรุปเหมือนเดิมและแน่นขึ้น:**

| | จำนวน |
|---|---|
| การ์ด `unformatted` | 25 |
| ไม่มีการ์ด | 2 |
| **รวมที่เก็บอะไรไม่ได้เลย** | **27 / 34** |
| ฟิลด์ ANR ในเฟิร์มแวร์ | **ไม่มี** |

→ **ไม่มี replay ทั้งกับเราและกับ CIB** · spool ตั้ง 1 ชม.พอ ไม่ต้อง 6 ชม.แบบ ANPR

### ค. CIB แจ้งแล้ว — ไม่ต้องส่งจดหมาย

เจ้าของแจ้ง CIB เรียบร้อยแล้ว **ฝั่งเราแค่เขียนโค้ดให้รองรับก็พอ**

### 🔴 `C80-PT-SB-33` — ไม่ใช่ "ลืมตั้ง" แต่**ชี้มาที่เรา**

เจ้าของถามว่า "คือกล้องที่ไม่มี IP+auth ของ CIB ใช่ไหม" — **ใช่ครับ และมีมากกว่านั้น**

```xml
slot 1:  https://dashboard.dojojin.tech:443/face-push/474a0c30-b9a9-4786-a4f5-18e38cb28d5c
         protocolType=HTTPS · parameterFormatType=XML · addressingFormatType=hostname
         httpAuthenticationMethod=none · httpBroken=false
```

**slot 1 ของมันชี้มาที่ตัวรับ face-push ของเรา** ไม่ใช่ CIB — น่าจะเป็นของเหลือจากการทดลอง IM3-R

**แต่ token นั้นตายแล้ว** — `474a0c30…` ไม่ตรงกับกล้องตัวไหนใน `cameras-config.json`
(ที่มี token จริงคือ `Hikvision_FaceReg_C01` และ `C59-PKT-SB-17` คนละค่า)
→ push ของมันถูก `facePushTokenGate` ทิ้งทั้งหมดในฐานะ unknown token

**ตรงกับคอมเมนต์ที่มีอยู่แล้วในโค้ด** (`routes/face-push.js` LIVE-HIGH-001):
*"observed sustained ~2 req/s of unknown-token /face-push hits in production logs since 2026-07-17"*

**สถานะจริงของ C80 ตอนนี้:**

| | |
|---|---|
| ส่งให้ CIB | ❌ **ไม่เคยส่งเลย** |
| ส่งให้เราทาง push | ❌ ถูกทิ้ง (token ตาย) |
| ส่งให้เราทาง pull alertStream | ✅ ปกติ — 284 ครั้ง/24 ชม. |

### 💡 และมันเปิดทางลัดให้ Phase 4

C80 **กำลังยิง XML ผ่าน tunnel มาหาเราอยู่แล้ว** — ถ้าเราแค่ใส่ `face_push_token = 474a0c30…`
ให้มันใน config, push จะเริ่มลงทันที **โดยไม่ต้องแตะกล้องแม้แต่ตัวเดียว**

→ ได้ payload XML จริงไปเขียน parser (Phase 4) **โดยข้าม Phase 3 ไปเลยได้**

> ⚠️ ต้องยืนยันก่อนว่ามันยัง push อยู่จริง — log ล่าสุดยังไม่เห็น unknown-token

## Phase 2 — ขยายความจุส่งออกไป CIB — ✅ ปิดแล้ว 2026-08-05 (`adf0b87`)

**สิ่งที่วัดได้วันนี้:**

```
ชั่วโมงพีค 17:00 วันนี้    444 ใบ/นาที      (เฉลี่ย 7 วัน 320 · วันนี้มากกว่า 39%)
เพดานส่งต่อ CIB ที่วัดได้   423 ใบ/นาที      ← ชนกันพอดี
ผลลัพธ์                   คิวค้าง 4,585 รายการ ทรงตัวมา 1 ชม.
```

**เพดานไม่ได้อยู่ที่ท่อ — อยู่ที่จำนวนสาย:**

| | ค่า |
|---|---|
| แบนด์วิดท์ขาออกจริงที่วัดได้ | **74 Mbps** (คอมเมนต์ในโค้ดยังเขียนว่า 44 — อัปเกรดแล้วแต่ไม่ได้ปรับค่า) |
| ANPR ใช้จริง | 423 × 985 KB = **55 Mbps** |
| `maxConcurrent` | **4** (ค่า default — `routes/lpr.js` ไม่เคยตั้ง) |
| ตัวระบายคิวใช้ | 3 · **เหลือให้ของสดแค่ 1 ช่อง** |

**กลไกที่ทำให้คิวเลี้ยงตัวเอง:** `if (_inFlight >= maxConcurrent) → spool ทันที`
พอมีคิวค้าง ตัวระบายกิน 3 ช่อง ของสดเหลือ 1 → ป้ายใหม่ตกคิวเกือบหมด →
คิวไม่มีวันลดจนกว่ารถจะเบาบางจริง (log ยืนยัน: `sent=1573 overflow=1562`)

| # | ทำอะไร | ค่า | สถานะ |
|---|---|---|---|
| 2.1 | เพิ่ม `maxConcurrent` **4 → 6** | ~630 ใบ/นาที ≈ 82 Mbps · ของสดได้ 5 ช่องแทน 1 | ✅ commit `adf0b87`, deploy+restart `lpr-receiver` ที่ hkt แล้ว |
| 2.2 | วัดผล 1 ชั่วโมงในชั่วโมงพีค | คิวต้องระบายจนว่าง ไม่ใช่ทรงตัว | ✅ **ผ่าน** — ดูหลักฐานด้านล่าง |
| 2.3 | แก้คอมเมนต์ "44 Mbps" ให้ตรงกับที่วัดได้ | กันคนหลัง | ✅ commit เดียวกับ 2.1 |

> ⚠️ **ขยับทีละขั้น ห้ามกระโดด** — คอมเมนต์ในโค้ดบันทึกไว้ว่าเคยเผลอเปิด ~7,000 สาย
> พร้อมกันจน *"effectively flooding a government endpoint"* · เลือก 6 ไม่ใช่ 8
> เพราะ 8 (~110 Mbps) จะเกินท่อจริง 74 Mbps แล้วไปเบียด face/tunnel

**ทำไมต้องก่อน Phase 5:** Phase 5 คือจุดที่ CIB **เลิกรับจากกล้องตรง มารับจากเราแทน**
ถ้าเรายังคอขวดอยู่ = เราทำให้ระบบภาครัฐช้าลงกว่าเดิม ซึ่งแย่กว่าไม่ทำอะไรเลย

**ทำไมเลือกกล้องตัวนี้:** traffic ไม่หนัก · ไม่ใช่จุดสำคัญ · **การ์ด SD ใช้ไม่ได้** จึงไม่มีตัวแปรเรื่อง replay มากวนตอนวัดผล

**เตรียมไว้แล้ว:** ล้าง `face_forward_url` ของกล้องนี้ออกแล้ว — relay จะไม่ยิง (ถ้ายิงจะซ้ำกับที่กล้องส่ง CIB ตรงอยู่ และเป็น format ที่เขาอ่านไม่ออก)

**เกณฑ์เสร็จ:** ได้ตัวอย่าง payload XML จริง · slot 1 ไม่เปลี่ยนแม้แต่ไบต์เดียว (เทียบกับ backup F1)

## Phase 4 — เขียน XML parser 🟡 **ต้องมี payload จาก Phase 3 ก่อน**

**ที่มา:** กล้องตั้ง `parameterFormatType = XML` ทั้ง 33 ตัว (CIB อ่าน XML)
แต่ `helpers/face-multipart.js` ของเรา**อ่านเฉพาะ `application/json`** — part ที่เป็น XML ตกไปเงียบ ๆ

```
กล้อง --XML--> CIB      ✅ ใช้ได้ทุกวันนี้
กล้อง --XML--> เรา      ❌ parse ไม่ได้
กล้อง --JSON--> เรา     ✅ แต่ CIB อ่านไม่ออก
```

| # | ทำอะไร |
|---|---|
| 4.1 | เขียน parser ฝั่ง XML จาก payload จริงที่เก็บได้ใน 3.5 |
| 4.2 | เทสต์ด้วย fixture จากของจริง เทียบผลกับที่ได้จาก alertStream ของกล้องเดียวกัน |
| 4.3 | ยืนยัน ingest ได้ครบ: ใบหน้า + ภาพ + appearance |

> **ทำไมแปลง JSON→XML แล้วส่งต่อไม่ได้:** จะไม่ใช่ byte-for-byte อีก
> แปลงผิดแม้แต่ field เดียว = ส่งข้อมูลผิดให้ระบบภาครัฐ **แย่กว่าไม่ส่ง**

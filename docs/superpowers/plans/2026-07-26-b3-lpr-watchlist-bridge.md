## ปัญหา

`blacklist.*` เป็น **คลังข้อมูล ไม่ยิงแจ้งเตือน** (ตั้งใจ — spec §1) ส่วนตัวที่ยิงจริงคือ
`lpr_watchlist` ซึ่งตอนนี้ **ว่างเปล่า 0 แถว** ผลคือทะเบียนเฝ้าระวัง 1,596 รายการที่
import เข้ามาแล้ว **ยังไม่ทำให้เกิดการแจ้งเตือนแม้แต่ครั้งเดียว** — ดูได้อย่างเดียว

จุดที่ match จริง (`src/routes/lpr-alerts.js:23`):
```sql
JOIN lpr_watchlist w ON w.plate_number = UPPER(lp.plate_number) AND w.active
```

migration 093 เตรียมคอลัมน์รอไว้แล้ว (`db/db_migration_093_blacklist_schema.sql:98`):
```sql
ALTER TABLE lpr_watchlist
  ADD COLUMN origin TEXT NOT NULL DEFAULT 'manual',   -- 'manual' | 'blacklist_bridge'
  ADD COLUMN blacklist_master_id BIGINT;
```
`origin` คือกลไกความปลอดภัย — bridge แตะเฉพาะแถวที่ตัวเองสร้าง **ไม่แตะแถวที่คนกรอกเอง**

## ข้อเท็จจริงที่ตรวจแล้ว (2026-07-26 — อย่าเดาซ้ำ)

### LINE ไม่ท่วม — เพราะยังไม่มีใครส่งเลย
`notify_line` มีคนเขียน/อ่านแค่ที่ `src/routes/lpr-watchlist.js` (CRUD) — **ไม่มี sender ตัวไหน
consume มัน** และ `alert-engine.js:46` ทำงานจาก `alert_rules` คนละตาราง ซึ่ง enabled = 0 กฎ

> ⚠️ ข้อนี้เคยรายงานผิดว่า "LINE จะท่วม 1,258 ข้อความ" — **ไม่จริง** แก้แล้ว
> แต่ถ้าวันหลังมีคนต่อ LINE เข้ากับ watchlist hit ข้อกังวลนี้จะกลับมาทันที

### ผลกระทบจริงคือแท็บ "แจ้งเตือน" ในหน้า LPR
```
ถ้า sync ครบ → ขึ้นย้อนหลัง 2,974 รายการ · 7 วันล่าสุด 2,451 · 24 ชม. 393
```
~16 รายการ/ชม. ในลิสต์ที่มีปุ่ม ack — ไม่พัง แต่ควรรู้ก่อนกด

### format ทะเบียนไม่ตรงกัน — ต้อง normalize
```
กล้องเราอ่านได้แบบมีช่องว่าง : 0 จาก 2,930,621   ← สะอาด 100%
DSS Pro มีช่องว่าง          : 46 / 516          ← คนพิมพ์ ไม่ใช่ OCR
GuruSquare มีช่องว่าง       : 100 / 1,080
```
ถ้าไม่ normalize จะพลาด **25 คัน** (exact 223 → normalize 248)

### แสดงผลไม่ต้องเก็บของดิบ
`dashboard/lpr-plaque.js:36` มี `\s*` ใน regex แยก prefix/number ให้เองอยู่แล้ว
`"1กค9136"` → prefix `1กค` + number `9136` แสดงแยกช่องบนป้าย
→ **ไม่ต้องเพิ่มคอลัมน์ `plate_display`**

### กลุ่มปลายทาง — ต้องโชว์ชื่อ ไม่ใช่ id
`lpr_watchlist_groups`: `suspect`/`warrant`/`vip` → `รถผู้ต้องสงสัย`/`รถตามหมายจับ`/`รถ VIP`
กลุ่ม rename ได้ (`wlGroupRename`) → ผูก id ในใจคนใช้ไม่ได้

### ข้อจำกัดของข้อมูลต้นทาง
| แหล่ง | group_name | กรองตามความเสี่ยงได้ไหม |
|---|---|---|
| DSS Pro | High Risk 351 · Medium Risk 159 · ทั้งสอง 4 · ไม่มี 2 | ✅ |
| GuruSquare | **null ทั้ง 1,080** | ❌ ได้แค่ "ทั้งหมด" / "เลือกเอง" |

## การตัดสินใจเชิงออกแบบ

### 1. กลไกเดียว 3 พรีเซ็ต — ไม่ใช่ 3 โหมด
"ทั้งหมด" = ตัวกรองที่ไม่กรอง · "เฉพาะป้าย" = เลือกหลายรายการที่เลือกอันเดียว
เขียนแยก 3 ทาง = โค้ด 3 ชุดที่พังคนละแบบ

| พรีเซ็ต | กติกาที่บันทึก | ตัวอย่าง |
|---|---|---|
| ทั้งหมดจากแหล่งนี้ | `source=DSS` | 516 |
| ตามระดับความเสี่ยง | `source=DSS, group_name=High Risk Vehicle` | 351 |
| เลือกเอง | `source=DSS, ids=[...]` | ตามที่ติ๊ก |

### 2. บันทึก "กติกา" ไม่ใช่ "รายการ" — sync ต้องต่อเนื่อง
copy ครั้งเดียวถอนของออกไม่ได้ → ถ้าต้นทางถอนชื่อคนที่พ้นข้อกล่าวหา แล้วเราไม่ถอนตาม
= เตือนรถคันนั้นตลอดไป (spec §4.4 ระบุ "Must also remove" ไว้ชัด)

### 3. normalize ที่ "ประตูเขียน" ไม่ใช่ที่ join
```sql
-- ❌ ห้ามทำ — index ใช้ไม่ได้ สแกน 2.93M แถวทุกครั้ง (บทเรียน LPR stats 17.85s)
JOIN lpr_watchlist w ON w.plate_number = UPPER(REGEXP_REPLACE(lp.plate_number, ...))
```
ให้ normalize ที่ทางเขียน **ทั้ง 2 บาน** แล้ว join เดิมทำงานได้โดยไม่แตะ:
- bridge sync
- `src/routes/lpr-watchlist.js` (ที่เจ้าหน้าที่กรอกเอง — ที่มาของ 46 แถวใน DSS)

ใช้ `normalizePlate()` ที่มีอยู่แล้วใน `src/helpers/blacklist-crypto.js` ห้ามเขียนใหม่

### 4. ทำที่หน้า "ฐานข้อมูลป้ายทะเบียน" ไม่ใช่หน้าตั้งค่า
คนที่ตัดสินใจว่า "คันนี้ควรเตือน" กำลังดูไทล์ + ตัวกรองอยู่ตรงนั้นแล้ว

## กับดักที่ต้องระวัง

1. **ห้ามลบแถว `origin='manual'`** — เงื่อนไข `WHERE origin='blacklist_bridge'` ต้องมีทุก DELETE
   ไม่งั้นข้อมูลที่เจ้าหน้าที่กรอกเองหายทั้งหมด
2. **`plate_number` เป็น PK** — ทะเบียนซ้ำระหว่าง manual กับ bridge จะชนกัน ต้องตัดสินใจว่า
   ใครชนะ (ข้อเสนอ: manual ชนะ bridge ข้ามไป + รายงานว่าข้ามกี่แถว — ห้ามเงียบ)
3. **`group_id` เป็น FK `ON DELETE SET NULL`** — ถ้าลบกลุ่มทิ้ง แถว bridge จะกลายเป็นไร้กลุ่ม
   ไม่ใช่หายไป
4. **GuruSquare ไม่มี group_name** → UI ต้องซ่อน/disable ตัวกรองความเสี่ยงเมื่อเลือกแหล่งนี้
   ไม่ใช่โชว์ dropdown ว่างให้งง

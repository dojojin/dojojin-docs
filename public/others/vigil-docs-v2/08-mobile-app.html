08 Vigil Mobile App (แอปพลิเคชัน Mobile)

ภาพรวม

Vigil Mobile App เป็น native iOS + Android companion app สำหรับ security operators ให้ติดตามกล้องและแจ้งเตือนในมือ ขณะไม่อยู่ที่โต๊ะ

การพัฒนา

  • Framework: React Native (Expo)
  • ภาษา: JavaScript + TypeScript
  • เวอร์ชัน: v1.4.0+ (parallel release กับ Vigil v1.4.0)
  • Repository: dojojin/vigil-mobile (แยกจากแพลตฟอร์มหลัก)
  • UI Score: 90/100 (WCAG AA compliant, responsive)

การจัดจำหน่าย

  • iOS: App Store (TestFlight สำหรับการทดสอบภายใน)
  • Android: Google Play Store (+ APK direct)
  • Enterprise: MDM distribution ผ่าน Intune/MobileIron
  • Custom: White-label build (แทนที่ชื่อแอป/icon/สี) ต่อ partner

คุณสมบัติหลัก — 5 Tabs

1. Alerts Tab (แท็บแจ้งเตือน)

Real-time stream ของ system alerts ส่งมาเป็น push notification

  • Live alert list (ใหม่สุดก่อน)
  • Tap เพื่อไปดู → event detail + snapshot
  • Swipe เพื่อ acknowledge/dismiss
  • Filter ตาม camera หรือ alert type
  • Sound + vibration (สามารถปิดเสียงได้)

2. Events Tab (แท็บเหตุการณ์)

ค้นดู events ทางประวัติศาสตร์ด้วย timeline

  • Scrollable timeline (24h, 7d, 30d views)
  • Event cards: camera, type, time, snapshot
  • ค้นหาตาม camera + date range
  • Tap สำหรับรายละเอียดเต็ม + pre-alarm video

3. Map Tab (แท็บแผนที่)

ตำแหน่งกล้องบน OpenLayers map

  • Real-time camera markers (เขียว=online, แดง=offline)
  • Zoom/pan, clustering ที่ zoom ต่ำ
  • Tap marker → camera details + live snapshot
  • Heatmap toggle (optional, heat-dense zones)

4. Settings Tab (แท็บการตั้งค่า)

ตั้งค่าแอป + config ระบบ

  • Custom Server URL: ชี้ไปยัง deploy ของลูกค้า (ไม่ hardcoded)
  • Username/Password: basic auth + device fingerprint
  • Push notification toggle
  • ภาษา: TH / EN
  • Logout

5. Profile Tab (แท็บโปรไฟล์)

ข้อมูลผู้ใช้ + biometric login

  • Display name + role (operator, viewer, etc.)
  • Biometric auth: Face ID (iOS), Fingerprint (Android)
  • Last login time
  • เกี่ยวกับ + version info

การพิสูจน์ตัวตน & ความปลอดภัย

Flow (การไหลของข้อมูล)

1. ผู้ใช้ใส่ custom server URL (เช่น https://vigil.customer.com)
2. ใส่ username + password
3. Backend ตรวจสอบ ส่งคืน JWT token + device fingerprint (hardware ID + app sig)
4. แอปเก็บ token ใน encrypted AsyncStorage
5. เมื่อเริ่มแอปใหม่: ตรวจสอบ token expiry + device fingerprint match
   → ถ้าถูก: auto-login (แสดง biometric prompt ถ้าเปิดใช้)
   → ถ้าไม่ถูก: force re-login
6. Biometric (Face ID / Fingerprint) unlock เท่านั้น (extra layer ไม่ใช่ replacement)

การจัดการ Token

  • Access token: หมดอายุ 15 นาที + refresh token
  • Refresh token: 7 วัน เก็บแบบ encrypted
  • Device fingerprint: ป้องกัน token ที่ถูกขโมยจากการใช้บน device อื่น
  • Logout: revoke token บน backend ล้าง AsyncStorage

Push Notifications (แจ้งเตือน Push)

การนำไปใช้

  • บริการ: Firebase Cloud Messaging (FCM, Android) + Apple Push Notification (APNs, iOS)
  • Trigger: Backend ส่ง push เมื่อ alert rule ถูกทำให้ทำงาน (ผ่าน LINE API integration หรือ direct FCM API)
  • Payload: alert_id, camera_name, event_type, timestamp, snapshot_url
  • พฤติกรรม: tap notification → ไปยัง alert detail ใน Alerts tab

สิทธิ์การเข้าถึง

  • iOS: ขออนุญาต notification เมื่อเปิดใช้ครั้งแรก (ผู้ใช้สามารถเพิกถอนใน Settings)
  • Android: Manifest permission + runtime permission (Android 13+)

Offline Resilience (ความยืดหยุ่นแบบออฟไลน์)

  • ไม่มี network: แสดง cached data (ได้นาน 24 ชั่วโมง) + "offline" badge
  • Network กลับมา: auto-sync alerts + events
  • Push ขณะออฟไลน์: deliver เมื่อเชื่อมต่อใหม่ (FCM จัดการ retries)
  • Stale token: ถ้าไม่มี network 7 วัน force logout ขณะเชื่อมต่อใหม่ (security + ป้องกัน stale auth)

ประสิทธิภาพและเมตริก

เมตริก เป้าหมาย ทำได้แล้ว (v1.5.1)
ขนาดแอป <50 MB 45 MB (iOS), 48 MB (Android)
เวลาโหลดครั้งแรก <3s 2.2s (WiFi), 3.8s (4G)
Alert notification delay (จาก backend fire ไปยัง user notification) <5s 1–3s (FCM delivery)
การใช้หน่วยความจำ <150 MB 120 MB (idle)
การใช้แบตเตอรี่ (8 ชั่วโมง idle มี push เปิดใช้) <5% 3% (optimized location services ปิด)

เครื่องที่รองรับ

แพลตฟอร์ม เวอร์ชั่นต่ำสุด เครื่องอุปกรณ์
iOS iOS 14.0+ iPhone 11+, iPad (6th gen+)
Android Android 11+ (API 30) Samsung, Xiaomi, Oppo, Vivo, OnePlus (ทั้งหมด major)

Internationalization (การจัดการหลายภาษา)

  • ภาษา: Thai (th_TH), English (en_US)
  • ค่าเริ่มต้น: จับคู่กับ device locale สามารถ override ใน Settings
  • สตริง: เก็บไว้ใน `locales/` JSON files (ไม่ hardcoded)
  • อนาคต: Vietnamese, Indonesian, Malay (Ph.5)

Roadmap (หลัง v1.5.1)

  • Ph.5 (Q3 2026): Multi-language (VI, ID, MS), QR code login, dark mode
  • Ph.6 (Q4 2026): Offline event search, advanced filters, analytics mini-charts

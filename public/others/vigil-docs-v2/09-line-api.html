09 LINE API Integration (การใช้งาน LINE API)

ภาพรวม

LINE Messaging API เป็นช่องทางหลักสำหรับแจ้งเตือนเหตุการณ์ไปยัง security operators และผู้บริหารในไทย ลูกค้าสามารถสมัครสมาชิก (subscribe) ผ่าน QR code ที่แดชบอร์ดเพื่อรับการแจ้งเตือน (alert) ส่วนตัว

ไหลของสถาปัตยกรรม

Alert Rule Match (Event Detected)
  ↓
Check enabled LINE notification (if yes)
  ↓
Download snapshot from camera
  ↓
Generate alert payload (message + image)
  ↓
Prepare LINE Message API request
  ↓
Rate limiter check (10 msg/sec per channel)
  ↓
Call Line Push Message API
  ↓
Log result (success / retry / failed) → audit_logs

รูปแบบข้อความ LINE

การแจ้งเตือน (Alert Notification)

From: @Vigil-Platform (Official Account)

Header: [ALERT] Motion Detected - North Gate

การตั้งค่า QR Code ด้วยตนเอง

ขั้นตอนการใช้งานของผู้ใช้ในแดชบอร์ด:

  1. ไปที่ Settings (การตั้งค่า) → Notifications (การแจ้งเตือน)
  2. คลิก "Subscribe to LINE alerts" (สมัครสมาชิก LINE alerts)
  3. สแกน QR code ด้วยแอป LINE (เปิด Official Account friendship modal)
  4. ยืนยันการเป็นเพื่อน (ระบบสร้าง webhook token ในพื้นหลัง)
  5. แดชบอร์ดเปลี่ยนไปพร้อมข้อความสำเร็จ + "You're subscribed"
  6. ระบบเริ่มส่งการแจ้งเตือนไปยัง LINE ID ของผู้ใช้

การตั้งค่า Webhook

Backend Endpoint (จุดปลายทาง Backend)

POST /api/integrations/line/webhook

  • ยืนยัน X-Line-Signature header (HMAC-SHA256 ของ body)
  • แยกวิเคราะห์เหตุการณ์ (follow, unfollow, message, postback)
  • เก็บ/อัปเดตการสมัครสมาชิกผู้ใช้ในตาราง line_subscriptions
  • ส่งตอบ 200 OK ไปยัง LINE server ภายใน 3 วินาที

เหตุการณ์ที่จัดการ

  • follow: ผู้ใช้เพิ่ม Official Account → สมัครสมาชิก alerts โดยอัตโนมัติ
  • unfollow: ผู้ใช้ลบ Official Account → ทำเครื่องหมายว่าการสมัครไม่ใช้งาน
  • message: ผู้ใช้ส่งข้อความ (เช่น "subscribe", "unsubscribe")
  • postback: ผู้ใช้คลิกปุ่ม (เช่น "view dashboard")

โควต้าและการจำกัดอัตรา

ขีดจำกัด LINE API

ขีดจำกัด ประเภท การกระทำ
1,000 ผู้ติดตามต่อวัน Soft (สามารถขอเพิ่มได้) ขอเพิ่มขีดจำกัดจาก LINE
20 ข้อความ/วินาที ต่อ bot Hard (บังคับ) คิวและลองใหม่แบบ exponential backoff
ขนาดภาพ ≤1 MB Hard (บังคับ) บีบอัดภาพให้ <500 KB
ความยาวข้อความ ≤1000 ตัวอักษร Hard (บังคับ) ตัดทอนหากจำเป็น

ขีดจำกัดอัตรา Vigil ภายใน

  • ต่อช่องทาง: สูงสุด 10 ข้อความ/วินาที (ต่ำกว่าขีดจำกัด 20 msg/sec ของ LINE)
  • ต่อผู้ใช้: สูงสุด 100 alerts/ชั่วโมง (ป้องกันความเหนื่อยหน่ายจากการแจ้งเตือน)
  • การจัดการการกระชาก: คิวไปที่ Redis และประมวลผลด้วย async worker
  • การติดตามตรวจสอบ: ติดตามอัตราความสำเร็จในการส่ง แจ้งเตือนหากอัตราการหล่นนอก >2%

การตั้งค่า

ตัวแปรสภาพแวดล้อม (บังคับ)

LINE_BOT_CHANNEL_ID=123456789...
LINE_BOT_CHANNEL_SECRET=abcdef123456...
LINE_BOT_ACCESS_TOKEN=
LINE_BOT_WEBHOOK_URL=https://dashboard.customer.com/api/integrations/line/webhook

แผงการจัดการแดชบอร์ด

  • ปุ่มทดสอบ webhook (ส่งการแจ้งเตือนตัวอย่าง)
  • ดูจำนวนการสมัครสมาชิก + การส่งล่าสุด
  • ปิด/เปิด LINE notifications ทั่วโลก
  • แก้ไขแม่แบบการแจ้งเตือน (ปรับแต่งข้อความ)

ข้อควรพิจารณาด้านความปลอดภัย

การยืนยันลายเซ็น

ทุกคำขอ webhook ของ LINE มี header X-Line-Signature: HMAC-SHA256(body, secret)

1. Compute: signature = base64(HMAC-SHA256(req.body, LINE_BOT_CHANNEL_SECRET))
2. Compare: signature == X-Line-Signature header
3. If match: process request
4. If not: reject (log + 400 Unauthorized)

ความเป็นส่วนตัวของข้อมูล

  • ID ผู้ใช้: เก็บ LINE User ID (ไม่เปิดเผย ไม่สามารถย้อนกลับเป็น personal ID)
  • ภาพ: รูปภาพสแนปชอตชั่วคราว (ลบหลังจาก 7 วัน)
  • ข้อความ: ไม่บันทึกข้อความ (เก็บเฉพาะข้อเท็จจริงของการส่ง + สถานะ)
  • เลิกใช้: ผู้ใช้สามารถยกเลิกติดตาม Official Account ได้ตลอดเวลา

การแก้ปัญหา

ปัญหา สาเหตุหลัก วิธีแก้
ไม่มีการแจ้งเตือน Token ไม่ถูกต้อง / webhook ไม่ทำงาน / rate limit ตรวจสอบความสำเร็จของ token ยืนยัน webhook URL เพิ่มจำนวน worker processes
Webhook ตอบ 429 ส่งข้อความ >20 msg/sec ไปยัง LINE ลดความถี่ ใช้งาน queue + async worker
ยืนยันลายเซ็นล้มเหลว channel secret ผิด ปัญหาเวลา ยืนยัน .env ตรวจสอบการซิงค์นาฬิการะบบ เปิดใช้งาน logging
ไม่แสดงภาพ URL รูปภาพหมดอายุ / เข้าไม่ได้ ตรวจสอบว่ารูปภาพยังอยู่ในดิสก์ ตรวจสอบเครือข่ายกล้อง

การปรับปรุงในอนาคต (Ph.5+)

ปุ่มเมนูที่หลากหลายใน LINE chat (เช่น "View Event", "Acknowledge", "Snooze 1hr") ซึ่งช่วยให้ operators สามารถตอบสนองต่อการแจ้งเตือนได้โดยตรงโดยไม่ต้องเปิดแดชบอร์ด

สถาปัตยกรรม Multi-Site (Edge ↔ ส่วนกลาง Cloud)

Site ต้นทาง (BMA / ภูเก็ต · 200 กล้อง/site) ประมวลผลในพื้นที่ → ส่งเข้าส่วนกลางบน Bangmod.Cloud ผ่าน WireGuard

DRAFT · ร่างออกแบบ
⚠ ระวังชื่อชนกัน: vigil-edge-01 = VM gateway บน Cloud (Public IP + WireGuard + nginx) — คนละตัวกับ "Site Edge" (เครื่อง N150 ที่ BMA/ภูเก็ต). ในเอกสารนี้: "Edge / ต้นทาง" = เครื่องที่ site เสมอ · "vigil-edge-01" = gateway บน cloud

1 · ภาพรวม — current → target

ปัจจุบัน: ทุกอย่าง (ingester + DB + dashboard) รันรวมเครื่องเดียว (Mac, Cloudflare Tunnel).

เป้าหมาย (multi-site): แยกเป็น 2 ชั้น —

  • Site Edge (ต้นทาง) = เครื่องเล็ก (N150) ในแต่ละ Site → คุย LAN กับกล้อง, normalize event, buffer (ANR), ส่งออกผ่าน WireGuard
  • ส่วนกลาง (Central) = Bangmod.Cloud 3 VMs → api-server + EMQX + PostgreSQL(RLS) + dashboard เดียวรวมทุก Site
  • ข้อมูลทุกชิ้นติด site_id → แยกการเข้าถึงด้วย RLS (Row-Level Security) ที่ vigil-db-01
หมายเหตุจำนวนกล้อง: "200 กล้อง/site" = ตัวเลขออกแบบเผื่อ (planning headroom) — spec cloud / OPEX / sizing ทั้งเอกสารคิดที่ 200 เพื่อไม่ต้องย้าย-ขยายของกลางทาง. ช่วง POC + deploy แรกจริงกล้องยังไม่ถึง 200 (เริ่มไม่กี่ตัว) แล้วค่อยสเกลขึ้น → uplink/ต้นทุนจริงช่วงแรกจะต่ำกว่าในเอกสารมาก

5 · การเชื่อมต่อ ต้นทาง → ปลายทาง

Transport = WireGuard (site edge = WG peer → vigil-edge-01) → ได้ private net flat ระหว่าง site↔cloud. บน private net นี้เลือก app-layer ได้ 2 แบบ:

แนะนำ Pattern A — HTTP Forwarder
  1. ingesters → publish nanoMQ (local)
  2. forwarder → HTTPS POST ผ่าน WireGuard → nginx(vigil-edge-01) → ingest receiver บน vigil-core-01
  3. receiver ติด site_id → เขียน vigil-db-01 → pg_notify (เหมือน ingester เดิม)

ทำไม: ตรงกับ pattern ที่ build แล้ว (lpr-receiver + spool/retry) · เบา

Pattern B — MQTT Bridge (nanoMQ → EMQX กลาง)

nanoMQ bridge → EMQX บน vigil-core-01 → Rule Engine + subscriber เขียน DB. WireGuard ทำให้ B ง่ายขึ้นมาก (ไม่ต้อง tcp-tunnel แยกแล้ว) + core มี EMQX อยู่แล้ว → viable แต่ยังต้องทำ subscriber รับ normalized event ใหม่ · A เบากว่าเพราะ reuse ของเดิม

uplink (เข้า quota) ขึ้นกับ "ส่งอะไรต่อ event". รูปเต็ม/clip เก็บที่ site + ดู on-demand เสมอ — ต่างกันแค่ส่งอะไรไปก่อน:

7 · ความทนทาน (ANR) + รูปแบบ metadata + ตรวจ "ไซต์ล่ม"

  • ANR: disk buffer ที่ edge = store ตอนลิงก์ขาด, auto-backfill ตอนกลับมา (สำหรับ metadata; full-res = pull on-demand)
  • "ไซต์ล่ม" ตรวจเอง: spool โต / forwarder heartbeat ขาด = ทั้ง site ขาด — health ระดับ Site แยกจาก "กล้องตัวเดียวล่ม"
metadata เก็บรูปแบบไหน: edge ingester normalize เป็น event JSON มาตรฐานเดียว (โครง events + raw_json เก็บ payload ดิบ) → buffer/forward เป็น JSON vendor-agnostic ทั้ง nanoMQ + spool · Central แค่ validate + INSERT (+site_id) ไม่มี logic ราย-vendor ที่กลาง

On-site media (Option A): operator ที่ site เปิด URL local → Caddy เสิร์ฟ dashboard + proxy /api→cloud (เล็ก) + เสิร์ฟ /media จากดิสก์ edge (LAN เร็ว, ไม่อ้อม cloud, 0 uplink) · remote → ผ่าน cloud ตามปกติ · control plane = cloud เสมอ, media plane = local-when-on-site

N150 รับไหว: ingest+nanoMQ+forwarder+WireGuard+Caddy ≈ <2.5GB/16GB · CPU แทบ idle · ตัวกิน spec จริงคือ clip/ffmpeg → เปิดเฉพาะกล้องสำคัญ · metadata-only/thumbnail ยิ่งเบา

Subdomain: dashboard.dojojin.tech → cloud (รวมทุก site, RBAC) · bma/phuket.dojojin.tech → edge LAN IP (A record → private IP, ใช้ได้เฉพาะตอนอยู่ on-site) + Caddy ใช้ wildcard cert *.dojojin.tech (DNS-01) → on-site ได้ HTTPS ถูกต้องไม่มี warning.
ชัดเจน (Q local-access): on-site = เฉพาะ "media" ที่ local · "data/API" ยังผ่าน cloud (single SoT, JSON เล็ก) · รูปที่ไม่อยู่ edge นี้ (ข้าม site / เกิน retention) → Caddy fallback ดึง cloud · auth share cookie ผ่านโดเมนแม่ *.dojojin.tech · ไม่กระทบ cloud/remote เลย (เป็น optimization ฝั่ง on-site ล้วน)

WireGuard มีต้นทุนไหม? — แทบไม่มี. WireGuard = open-source ฟรี · รันบน vigil-edge-01 (719฿ ที่จ่ายอยู่แล้ว) + N150 (มีอยู่แล้ว) → ไม่มี line-item เพิ่ม · Public IP ฟรีในแพ็กเกจ. traffic วิ่งใน 8TB transfer ของ VM (ingest = inbound ส่วนใหญ่ฟรี · media on-site เสิร์ฟ local ไม่กิน egress cloud). ไม่ต้องมี tunnel บน cloud (Public IP + WireGuard ครบ) · Cloudflare = optional CDN/DDoS หน้า dashboard เท่านั้น
ไม่ต้องพึ่ง Cloudflare media products: Images คิดราย-รูป → volume CCTV (ล้าน/เดือน) ระเบิด (LPR-heavy ~$1,800/เดือน ❌) · Stream = video เท่านั้น (clip เก็บ edge → ไม่ต้อง). ถ้าจะมี cloud object สำหรับ backup/durable-thumbnail → R2 ($0.015/GB + egress ฟรี · batch ลด per-operation) หรือ Bangmod Object (1฿/GB ไม่มี op-fee). แก่น: full-res ที่ edge = ถูกที่สุด

11 · แผนติดตั้ง Site Edge (BMA + ภูเก็ต)

ขั้นตอนร่วม (ทำเหมือนกันทั้ง 2 site) → แล้วต่างกันแค่ site profile:

ขั้นตอนร่วม (per edge)
  1. OS: ลง Ubuntu Server LTS บน N150 · เปิด SSH
  2. Network 2 NIC: onboard → camera subnet (static, ไม่มี default gateway) · USB → office/WAN (มี gateway + internet)
  3. WireGuard: apt install wireguard → gen keypair → ตั้ง peer = vigil-edge-01 (Endpoint=Public IP:51820, AllowedIPs=ช่วง private cloud) → wg-quick up wg0 → ยืนยัน handshake
  4. Runtime: Node 22 + PM2 → ดึง edge bundle (ingesters + forwarder + nanoMQ + Caddy)
  5. Edge Config (site profile): ตั้ง site_id · เปิด/ปิด vendor+capability · central endpoint (ผ่าน WG) · transfer mode (LPR=meta-only, Face=thumb) · thumbnail size · retention
  6. Caddy media-proxy: เสิร์ฟ dashboard + proxy /api→cloud + /media→local · bind USB(office) NIC · local TLS · auth ผ่าน session กลาง
  7. Autostart: PM2 save + systemd (boot ขึ้นเอง) · forwarder spool/retry เปิด
  8. Verify: WG handshake ✓ · ยิง event ทดสอบ → เห็นใน dashboard กลาง (ติด site_id ถูก) ✓ · เปิด media local ที่ site เร็ว ✓ · ถอด USB ชั่วคราว → spool โต แล้ว backfill เมื่อต่อกลับ ✓

BMA — site profile

  1. site_id = "bma" · 200 กล้อง
  2. เปิด ingester: 🟡 ตัวอย่าง (ปรับตาม inventory จริง) Hikvision (ANPR + Smart) · Bosch (MQTT) · Dahua (Smart)
  3. มี Bosch → เปิด nanoMQ
  4. LPR (ANPR) = metadata-only · กล้องทั่วไป = thumbnail
  5. internet: ตามปริมาณ event (ข้อ 8) — LPR เยอะ→พิจารณา Fiber

ภูเก็ต — site profile

  1. site_id = "phuket" · ≤200 กล้อง (เผื่อ)
  2. เปิด ingester: 🟡 ตัวอย่าง (ปรับตาม inventory จริง) Dahua (ANPR + Face + Smart) · Hikvision (ANPR)
  3. ไม่มี Bosch → ข้าม nanoMQ ได้ (ingester→forwarder ตรง ยิ่งเบาบน N150)
  4. LPR=metadata-only · Face=thumbnail
  5. internet: ตามปริมาณ event ราย-site

04 องค์ประกอบระบบ

ภาพรวมสถาปัตยกรรม (Architecture Overview)

Vigil Platform ประกอบด้วย 4 ชั้นหลัก: Ingestion (รับเหตุการณ์จากกล้อง), Backend API (ประมวลผล แจ้งเตือน สถิติ), Database (เก็บข้อมูล), และ Frontend (dashboard + mobile app)

ชั้น Frontend

Dashboard (Vanilla JS + Chart.js + OpenLayers)

  • Live dashboard: กล้อง เหตุการณ์ การแจ้งเตือน
  • Executive Summary: บรรยายสรุปตอนเช้า KPI
  • Analytics: กราฟเส้นเวลา แนวโน้ม
  • Settings: การตั้งค่ากล้อง กฎ ผู้ใช้
  • Map page: OpenLayers + CartoDB
  • Appearances: ค้นหา + กราฟวิเคราะห์

ชั้น Ingestion

Ingesters เฉพาะเจาะจงตามเวนเดอร์ (Node.js)

  • Bosch: MQTT listener (ONVIF Profile M)
  • Hikvision: ISAPI HTTP endpoint
  • Dahua: HTTP CGI listener
  • ตรวจสอบและปกติของเหตุการณ์
  • ดาวน์โหลดสื่อ (สแนปช็อต บทตัดกล้อง)

Backend API

Express.js REST API

  • ค้นหาเหตุการณ์ เส้นเวลา สถิติ
  • เอนจิน Alert rule
  • ส่งการแจ้งเตือน LINE
  • สร้างรายงาน (PNG วิเคราะห์)
  • ยืนยันตัวตนผู้ใช้ (JWT + session)
  • RBAC (admin viewer auditor)
  • Health check endpoint

ฐานข้อมูล

PostgreSQL (20+ ตาราง)

  • events — บันทึกเหตุการณ์หลัก
  • cameras — การตั้งค่ากล้อง
  • alert_rules, alert_logs
  • appearances — คุณลักษณะของบุคคล
  • users, audit_logs
  • นโยบายการเก็บรักษา (การลบโดยอัตโนมัติ)
  • Indexes + partition ตามวันที่

ที่เก็บสื่อ

Local filesystem + S3/NAS เพิ่มเติม

  • snapshots/ — รูปภาพเหตุการณ์
  • faces/ — บทตัดใบหน้า Hikvision
  • videos/ — คลิปก่อน alarm (Profile C)
  • Retention: ตั้งค่าได้แต่ละประเภท
  • Cleanup: ลบไฟล์เก่าโดยอัตโนมัติ

บริการสนับสนุน

  • EMQX (สำหรับ Bosch MQTT)
  • Redis (session cache real-time pub/sub)
  • PM2 (จัดการ process รีสตาร์ทอัตโนมัติ)
  • Cloudflare Tunnel (reverse proxy)
  • LINE API (bot webhook)
  • Puppeteer (health report PDF/PNG)

ลำดับการไหลของข้อมูล

รับเหตุการณ์ (Real-time)

กล้อง → [Bosch MQTT | Hik ISAPI | Dahua HTTP] → Ingester Node.js
        → ตรวจสอบ + ดาวน์โหลด snapshot/บทตัดใบหน้า
        → INSERT INTO ตารางเหตุการณ์
        → เผยแพร่ไปยังช่อง Redis (real-time)
        → ทำให้กฎ alert ทำงาน (ถ้าตรงกัน)
        → ส่งการแจ้งเตือน LINE (ถ้าเปิดใช้)
        → Return 200 OK

Frontend Real-time (WebSocket)

Frontend → การเชื่อมต่อ WS → Backend
         → [สมัครสมาชิกช่อง alert]
         → Backend เผยแพร่ alert ใหม่ผ่าน Redis
         → WS ส่งไปยังไคลเอนต์ทั้งหมดที่เชื่อมต่อ
         → UI อัปเดต (บัตรเหตุการณ์ใหม่ เสียง toast)

สร้างรายงาน

ผู้ใช้คลิก "สร้างรายงานสุขภาพ"
         → Backend สร้าง SVG template (_svgSafeText ลบ emoji)
         → Sharp (librsvg) render SVG → PNG (ไม่มี emoji = ไม่ abort)
         → ส่งลิงก์ดาวน์โหลด
         → PNG หมดอายุหลังจาก 24 ชั่วโมง (cleanup job)
หมายเหตุ: รายงาน PDF วิเคราะห์ใช้ Puppeteer — path แยกต่างหาก

ไฟล์การตั้งค่าหลัก

ไฟล์ วัตถุประสงค์ ตัวอย่าง
system_settings (ตาราง DB) การตั้งค่าระบบ (theme ภาษา วันการเก็บรักษา token LINE) จัดการผ่าน admin dashboard หน้า Settings
cameras-config.json รายชื่อกล้อง + auth credentials (เข้ารหัส AES-256-GCM at rest) URL กล้อง Bosch Hikvision Dahua + credentials ที่เข้ารหัส
.env ตัวแปร environment (secrets URL DB ports) DATABASE_URL, LINE_BOT_TOKEN, JWT_SECRET
ecosystem.config.js การตั้งค่า PM2 process Worker count memory limit restart policy
db/init.sql การเริ่มต้นฐานข้อมูล (ติดตั้งใหม่) CREATE TABLE + initial schema
db/db_migration_*.sql Migration schema แบบเพิ่มเติม ใช้ at startup ถ้ายังไม่ทำ

ลำดับการยืนยันตัวตนและการอนุญาต

1. เข้าสู่ระบบผู้ใช้ (username + password)
   → Backend ตรวจสอบ credentials (bcrypt)
   → สร้าง JWT token (httpOnly cookie)
   → สร้าง refresh token ด้วย (Redis)

2. ทุกการร้องขอ API
   → ไคลเอนต์ส่ง JWT ผ่าน httpOnly cookie (ไม่ใช่ header)
   → Middleware ตรวจสอบลายเซ็น + ความเท่า expiry
   → แยก user ID + role (admin/viewer/auditor)
   → ตรวจสอบสิทธิ์สำหรับ endpoint

3. การเข้าถึงแบบ role-based (RBAC)
   → admin: เข้าถึงเต็มที่
   → viewer: dashboard read-only
   → auditor: read-only + reports/export

4. Audit log
   → ทุก action ที่สำคัญบันทึกในตาราง audit_logs
   → User ID action timestamp IP address

ตัวเลือกการ Deploy

ตัวเลือก A: Docker

docker-compose up — stack all-in-one

  • Frontend (nginx)
  • API (Node.js)
  • PostgreSQL
  • Redis
  • EMQX (optional)

ตัวเลือก B: VM + PM2

Ubuntu/Debian + Node.js โดยตรง

  • Systemd service สำหรับ PM2
  • Nginx reverse proxy
  • PostgreSQL จัดการแยก
  • Redis จัดการแยก

ตัวเลือก C: Kubernetes

Helm chart (Roadmap)

  • Pod replicas
  • StatefulSet (DB)
  • Service mesh optional
  • Auto-scaling พร้อม

06 บั๊กที่แก้แล้ว

ระบบจริงต้องเผชิญกับ edge case ที่ซับซ้อน รวมถึง heisenbug ที่เกี่ยวข้องกับพฤติกรรม browser, caching, timing issues และ vendor-specific protocol quirks Vigil ได้ผ่านการทดสอบมาหลายรอบและเก็บบทเรียนไว้เป็น GOTCHAS.md ในโค้ด베ส

บั๊กหลักตามหมวดหมู่

MQTT และ Event Ingestion

  • #33/#112 — EMQX broker swap: สูญหาย Bosch MQTT events ขณะ broker failover เหตุ: subscription เก่าในไลบรารี client แก้ไข: ใช้ retry + reconnect logic พร้อม exponential backoff + ยืนยันลำดับข้อมูล
  • #39/#41 — Dahua CGI poll race: event ซ้ำกันเมื่อ Dahua ส่ง event ID เดียวกันในการ poll ครั้งต่อไป แก้ไข: ติดตาม last_event_id ต่อกล้องและละเว้นถ้าเห็นแล้วภายในเวลา 60 วินาที
  • #40 — Hikvision face crop stream hang: Multipart JPEG stream ของการจับภาพใบหน้าไม่ปิดในบางเวอร์ชัน firmware แก้ไข: หมดเวลาหลัง 5 นาที + บังคับ reconnect

ฐานข้อมูลและประสิทธิภาพ

  • #15 — N+1 query ใน event timeline: event 10,000 รายการ × 1 query ต่อกล้อง = 10,001 queries เหตุ: ขาด LEFT JOIN แก้ไข: รวมจำนวน event ต่อกล้องในคำค้นหาเดียว
  • #22 — Partition bloat: Event rows 500 ล้านรายการไม่มีการแบ่ง partition แก้ไข: เพิ่มการแบ่ง partition รายเดือน + auto-truncate partition เก่า
  • #45 — Full table scan ใน analytics: รายงาน 7 วันใช้เวลา 5 นาทีในการสร้าง แก้ไข: เพิ่ม indexes บน (camera_id, event_time, event_type)

Frontend และ Browser

  • #26/#108 — License fingerprint บน iPad: Hardware fingerprint เปลี่ยนหลังจาก reboot (Safari ITP + cached script) เหตุ: localStorage ถูกลบโดย ITP แก้ไข: triple-layer auth (JWT + sessionStorage + IP whitelist)
  • #29/#30/#31 — Mobile responsive collapse: Dashboard พังบน iPad (768px breakpoint หายไป) เหตุ: ความกว้างที่กำหนดในแบบ CSS แก้ไข: flex grid + media queries อย่างเคร่งครัด ≤768px
  • #42 — i18n string ถูกตัด: ข้อความภาษาไทยในการ์ดหลุดออกนอกเนื้อที่บน desktop เหตุ: font-family ไม่มี Noto Sans Thai แก้ไข: ใช้ -apple-system stack กับ Noto Sans Thai เป็นอันดับแรก

WebSocket และ Real-time

  • #53 — WS connection leak ในหน้า map: 100+ WS ที่เชื่อมต่อกับเซิร์ฟเวอร์เดียวกันหน่วยความจำเพิ่มขึ้น เหตุ: ไม่มีการทำความสะอาดเมื่อปิดหน้า แก้ไข: ws.close() ที่ชัดเจนใน beforeunload
  • #54 — Heartbeat หายไป: WS ถูกทำเครื่องหมายว่า "online" แต่ client ไม่เคยเชื่อมต่อจริงๆ เหตุ: ไม่มี ping/pong frame แก้ไข: ใช้ heartbeat 30 วินาที + ประกาศเสียหากไม่มี pong

Caching และข้อมูลเก่า

  • #50/#67 — Cloudflare cache stale JS: ผู้ใช้ได้รับ dashboard.js เก่านาน 24 ชั่วโมงหลังจาก deploy เหตุ: อายุ cache ของ Cloudflare นานเกินไปและไม่มี cache-bust header แก้ไข: เพิ่ม Content-Hash ในชื่อไฟล์ + ตั้ง Cache-Control: public, max-age=3600
  • #51 — Redis TTL ไม่ถูกนำมาใช้: Session ไม่เคยหมดอายุ เหตุ: EXPIRE command ไม่ได้ตั้งค่าเมื่อสร้างคีย์ แก้ไข: pipeline SET + EXPIRE ร่วมกัน

Media และการอัปโหลดไฟล์

  • #25/#25a — SVG emoji crash ใน Health Report: Puppeteer render SVG+emoji template librsvg abort เมื่อไม่มี emoji fallback font เหตุ: emoji ไม่ถูกลบออกจาก SVG แก้ไข: ใช้ _svgSafeText() เพื่อลบ emoji ก่อน render
  • #60 — Snapshot cleanup ไม่ทำงาน: Snapshot เก่าสะสมตลอดไป เหตุ: ปิดใช้งาน cron job โดยไม่ตั้งใจ แก้ไข: เปิดใช้งานอีกครั้ง + เพิ่มการแจ้งเตือนถ้าล้มเหลว 3 ครั้งติดต่อกัน
  • #75 — MediaRecorder decrypt miss: Pre-alarm video decryption ล้มเหลวเงียบ ๆ ผู้ใช้ได้ MP4 ที่เสียหาย แก้ไข: เพิ่มการยืนยัน SHA256 checksum + ลองใหม่ถ้าไม่ตรงกัน

Integration และบุคคลที่สาม

  • #36/#38 — LINE API quota throttle: ส่ง 100 alerts พร้อมกัน → 429 too many requests, alerts หล่น เหตุ: ไม่มี rate limiting แก้ไข: ใช้ queue + 10 msg/sec limit + exponential backoff retry
  • #37 — Mapbox tile 404 ไม่ graceful: Map ว่างเปล่าเมื่อ tile server ลง แก้ไข: fallback ไปยัง CartoDB ลองใหม่ด้วย exponential backoff

Operator Error และ Edge Case

  • #18 — Admin ลบกล้องโดยไม่มีการเตือน: Event 10,000 รายการไม่มีเจ้าของรายงานล้มเหลว แก้ไข: เพิ่มกล่องยืนยัน + cascade delete + audit log
  • #32 — Bosch + Hikvision ชื่อโมเดลเดียวกัน: Admin เพิ่มกล้อง 2 ตัวด้วยชื่อเดียวกัน UI สับสน แก้ไข: บังคับให้ camera_id + name ไม่ซ้ำกัน แสดงโมเดล + MAC address ในการเตือนเกี่ยวกับการซ้ำซ้อน
  • #76 — Offline camera churn: กล้องออฟไลน์ กลับมาออนไลน์ ออฟไลน์อีก → 3 event records ต่อวินาที เหตุ: การเปลี่ยนแปลงสถานะอย่างรวดเร็ว แก้ไข: debounce state changes โดย 30 วินาที

บทเรียน: กลยุทธ์การ Reproduce Heisenbug

เมื่อเจอ heisenbug ที่ไม่สามารถ reproduce ในสภาพแวดล้อม dev ให้ลองแนวทาง: (1) จำลองเงื่อนไข prod ให้แม่นที่สุด (network delay, load), (2) เปิด logging รายละเอียดในจุด suspicious, (3) ใช้ simulation tools (tc, stress-ng) ค่อย ๆ เพิ่ม load จนกระทั่ง repro ได้, (4) record ทั้งหมดใน GOTCHAS.md เพื่อป้องกันในอนาคต

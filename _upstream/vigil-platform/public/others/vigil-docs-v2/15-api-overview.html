15 ภาพรวม REST API

ภาพรวม

Vigil Platform เปิดให้ใช้งาน REST API ครบชุดสำหรับ operators, integrators และแอป Vigil Mobile เพื่อดึงข้อมูลเหตุการณ์ ค้นหา ตั้งค่ากฎแจ้งเตือน จัดการรายงาน และตรวจสอบสถานะระบบ — ทั้งหมดผ่าน HTTPS ที่ต้องผ่านการยืนยันตัวตน

  • Protocol: HTTPS REST (JSON request/response)
  • Realtime: WebSocket ต่อเดียวต่อ tab — push เหตุการณ์ใหม่โดยไม่ต้อง refresh
  • Auth: JWT-based, 3 วิธี (ดูหัวข้อถัดไป)
  • ทุก endpoint ที่ไม่ใช่ public ต้องผ่าน session ที่ valid

การยืนยันตัวตน (Authentication)

ระบบรองรับ 3 วิธีในการส่ง token — ทุกคำขอ API ตรวจสอบตามลำดับนี้:

วิธี รูปแบบ ใช้เมื่อ
Cookie (httpOnly) ตั้งอัตโนมัติเมื่อ login ผ่านเบราว์เซอร์ Dashboard มาตรฐาน — แนะนำสำหรับเบราว์เซอร์
Bearer Token Authorization: Bearer <token> API client, mobile app, third-party integration
URL Token ?token=<token> ลิงก์รายงาน PDF/PNG ที่ต้องการ auth โดยไม่มี header

ระดับสิทธิ์ (RBAC)

Role สิทธิ์
admin เข้าถึงได้ทั้งหมด — อ่าน เขียน ลบ จัดการผู้ใช้ ตั้งค่าระบบ
viewer อ่านอย่างเดียว — ดูเหตุการณ์ สถิติ แผนที่ กล้อง
auditor อ่าน + export รายงาน — ไม่สามารถเปลี่ยนการตั้งค่า
public ไม่ต้อง login — เฉพาะ endpoint ที่กำหนด (branding, health ping)

กลุ่ม API หลัก (API Groups)

กลุ่ม Path prefix สิ่งที่ทำได้ สิทธิ์ขั้นต่ำ
เหตุการณ์ /api/events ค้นหา กรอง ดูรูปสแนปช็อต ดูคลิปวิดีโอ · param exclude_types= ข้าม LPR/Face จาก feed viewer
การปรากฏตัวบุคคล /api/appearances ค้นหาลักษณะบุคคล timeline similarity viewer
ใบหน้า & Face Recognition /api/faces, /api/face-matches, /api/faces/counts ค้นหาภาพใบหน้าจาก Face Capture · รายการจับคู่จาก Hikvision Face Recognition + body appearance · จำนวน face viewer
ป้ายทะเบียน & Watchlist (ANPR) /api/lpr, /api/lpr/brands, /api/lpr/stats, /api/lpr/watchlist, /api/lpr/alerts, /api/lpr/camera-direction ค้นหาป้ายทะเบียนจาก Hikvision ITCCAM ANPR · keyset/cursor pagination (headers X-Has-More, X-Estimated-Count) · KPI วันนี้ (total/unique/top brand/plate-color/vehicle-brand) · filters: vehicle brand, color, pedestrian vehicle-type, seatbelt · watchlist (flag plates → alerts) · alert ack tab · lpr_direction ต่อกล้อง viewer / admin
สถิติ Face & Person /api/faces/stats, /api/appearances/stats, /api/faces/counts Face overview (peak/gender/age/expression) · Body appearance KPI + peak-by-hour/camera · จำนวน face unacked per type viewer
Sites (Multi-site) /api/sites CRUD sites (BMA/Phuket/Main) + provision edge bridge (POST /api/sites/:id/push-config) admin
กล้อง /api/cameras รายชื่อกล้อง + สถานะ online/offline + heartbeat viewer
สถิติ & Analytics /api/stats สถิติเหตุการณ์รายชั่วโมง/วัน กราฟแนวโน้ม viewer
แผนที่ & Heatmap /api/heatmap ข้อมูลความหนาแน่นสำหรับแผนที่ viewer
กฎแจ้งเตือน /api/alert-rules สร้าง/แก้ไข/ลบกฎ LINE alert + quiet hours admin
ประวัติการแจ้งเตือน /api/alert-logs ประวัติการส่ง LINE alert ทั้งหมด viewer
รายงาน /api/report-schedules ตั้งเวลารายงาน / สั่ง run ทันที admin
LINE Config /api/line ตั้งค่า LINE bot token + ผู้รับ + QR code admin
การตั้งค่าระบบ /api/settings ตั้งค่าทั่วไป ภาษา retention period และอื่น ๆ admin
ผู้ใช้ & Session /api/users จัดการบัญชีผู้ใช้ roles และ session ที่ active admin
สุขภาพระบบ /api/health สถานะ service กล้อง offline disk usage viewer
Branding /api/branding ชื่อ โลโก้ สีหลักของระบบ public
Auth /api/login, /api/logout เข้า/ออกระบบ ตรวจสอบ session public

WebSocket — Real-time Push

ทุก session ที่ login แล้วสามารถเปิด WebSocket connection เพื่อรับเหตุการณ์ใหม่แบบ real-time โดยไม่ต้อง reload หน้า

wss://<host>/ws   (ต้องมี session cookie หรือ Bearer token)

ประเภทข้อความที่รับได้

ประเภท เนื้อหา
new_event เหตุการณ์ใหม่จากกล้อง — ID ชนิด กล้อง เวลา มีรูปหรือไม่
camera_status กล้องเปลี่ยนสถานะ online/offline
alert_fired กฎแจ้งเตือนทำงาน — ส่ง LINE แล้ว
system ข้อความระบบ — เช่น service restart, migration สำเร็จ

ข้อควรทราบ

WebSocket ต้องมี session ที่ valid เสมอ — ถ้า session หมดอายุ connection จะถูกตัดและ dashboard จะแสดง toast "session expired" แล้ว redirect ไป login

รูปแบบ Response

สำเร็จ

HTTP 200 OK
Content-Type: application/json

// รายการ (list)
[{ "id": 1, "event_type": "Motion", ... }, ...]

// รายการเดียว หรือ action result
{ "id": 1, "enabled": true, ... }
{ "ok": true }

Error

HTTP 4xx / 5xx
{ "error": "คำอธิบายข้อผิดพลาด" }
HTTP Status ความหมาย
400ข้อมูลที่ส่งมาไม่ถูกต้อง (validation error)
401ไม่มีหรือ session หมดอายุ → ต้อง login ใหม่
403มี session แต่สิทธิ์ไม่พอ (เช่น viewer พยายามแก้ไข)
404ไม่พบ resource ที่ขอ
503Service ภายในไม่พร้อม (เช่น report-worker ยังไม่ start)

Pagination

Endpoint ที่คืนรายการจำนวนมาก (events, appearances, alert-logs) รองรับ query params ดังนี้:

GET /api/events?limit=50&offset=0&sort=desc
GET /api/appearances/search?limit=20&offset=0
  • limit — จำนวนรายการต่อหน้า (ค่าเริ่มต้นต่างกันตาม endpoint)
  • offset — ตำแหน่งเริ่มต้น (0 = หน้าแรก)
  • Response มี field total สำหรับคำนวณจำนวนหน้า

ตัวอย่าง: ดึงเหตุการณ์ล่าสุด

GET /api/events?limit=20&sort=desc
Authorization: Bearer <token>

สรุปการค้นหาความปลอดภัย

SEC-001–006: Infrastructure & Ingest

  • SEC-001: MQTT port wildcard bind → แก้ไข: EMQX AUTHN บังคับ credentials ทุก client; port binding อัปเดตเป็น 0.0.0.0:1883 (resilient ต่อการเปลี่ยน network) + rotate รหัสผ่าน EMQX
  • SEC-002: Stored XSS ผ่าน MQTT/DB fields ใน DOM → แก้ไข: escapeHtml() ทุก dynamic fields
  • SEC-003: Credentials รั่วไหลใน API response (non-admin) → แก้ไข: ซ่อนรหัสผ่านสำหรับ non-admin roles
  • SEC-004: Auth bypass เมื่อ must_change_password=true → แก้ไข: บังคับ flag ที่ middleware ไม่ใช่แค่ login page
  • SEC-005: File upload ตรวจสอบ MIME เท่านั้น → แก้ไข: magic bytes check (JPEG \xFF\xD8\xFF, PNG \x89PNG)
  • SEC-006: Security headers หายหรือไม่สอดคล้อง → แก้ไข: CSP Report-Only + HSTS เงื่อนไขตาม HTTPS

SEC-007–012: Dependencies Secrets & Session

  • SEC-007: qs library CVE → แก้ไข: อัปเกรด qs ≥6.13.1
  • SEC-008: SSRF probe (outbound ไปยัง private IPs) → แก้ไข: _isPrivateIp() warning (non-blocking สำหรับ on-prem)
  • SEC-009: .env entries ผิดรูป จากข้อผิดพลาด paste → แก้ไข: comment ไลน์ที่ไม่ถูกต้อง
  • SEC-010: Login/logout cookie flags ไม่ตรงกัน → แก้ไข: ใช้ flag builder เดียวกัน (HttpOnly SameSite=Lax Secure on HTTPS)
  • SEC-011: PostgreSQL port wildcard bind → แก้ไข: 127.0.0.1:5432 + rotate รหัสผ่าน
  • SEC-012: Secrets sprawl — ไฟล์ .env ที่ไม่มีเอกสาร → แก้ไข: secrets inventory checklist ทั้งหมด .env ใน .gitignore pre-commit hook

SEC-013: ส่วนอนุญาต Camera Config

  • SEC-013: cameras-config.json world-readable (permissions 644) → แก้ไข: chmod 600 ไฟล์ gitignored

SEC-014–017: Credential Encryption DB Cleanup & Proxy (รอบ 2)

  • SEC-014: Camera credentials เก็บ plaintext ใน cameras-config.json → แก้ไข: เข้ารหัส AES-256-GCM (enc:v1: format) decrypt-at-load
  • SEC-015: Dead columns (http_password, rtsp_url) ในตาราง cameras → แก้ไข: migration 038 ลบ dead columns
  • SEC-016: PostgreSQL ไม่มี TLS → แก้ไข: ssl=on (TLSv1.3) ผ่าน ALTER SYSTEM zero-downtime
  • SEC-017: Mapbox token เปิดเผยต่อเบราว์เซอร์ (network tab) → แก้ไข: backend proxy /api/map/tiles/mapbox/:style/:z/:x/:y.png (auth-gated cache-first)

SEC-2T-001–008: CDN, CSP, Error Leak & Role Drift (รอบ 3)

  • SEC-2T-001: ไฟล์ static ใช้ CDN ภายนอก (EmailJS, Materialize) → แก้ไข: ลบไฟล์ที่ไม่จำเป็น + auth-gate /others default-deny
  • SEC-2T-002: Inline onclick= / <script> ใน dashboard HTML ทำให้ CSP ไม่เข้มงวดได้ → แก้ไข: ย้ายทั้งหมดเป็น data-action dispatcher (zero inline scripts)
  • SEC-2T-004: Error response เปิดเผย stack trace หรือ internal path → แก้ไข: routeError() helper — ตอบ {error} สม่ำเสมอ ไม่มี stack trace
  • SEC-2T-005: GET /api/line-config ไม่บังคับ role → แก้ไข: viewer ถูกบล็อก เฉพาะ admin เท่านั้น
  • SEC-2T-006: Camera credentials ที่ยังเป็น plaintext ไม่มีการแจ้งเตือน → แก้ไข: /api/health/details warn เมื่อพบ credentials ที่ยังไม่เข้ารหัส
  • SEC-2T-007: express.static อาจเปิดเผย dotfiles (.env, .git) → แก้ไข: dotfiles: 'deny' ทุก static mount

EMQX Network Resilience (SEC-001 ปรับปรุง)

ปัญหา: EMQX bind กับ IP เฉพาะ (192.168.10.31:1883) ทำให้ container ไม่ start เมื่อ network interface ไม่มี (เช่น ย้ายที่ / เปลี่ยน LAN)

แก้ไข: เปลี่ยน port binding เป็น 0.0.0.0:1883 — EMQX start ได้ทุก network; security ยังคงอยู่ผ่าน EMQX AUTHN (credentials บังคับทุก client, SEC-001 Phase 2)

ผลลัพธ์: เมื่อ camera LAN กลับมา กล้องและ mqtt-subscriber.js reconnect อัตโนมัติโดยไม่ต้อง restart ใดๆ

สถานะ EOL ที่ต้องติดตาม

  • EMQX 5.8 OSS EOL: ก.พ. 2026 — ไม่มี security release ใหม่ใน 5.8.x แล้ว; plan upgrade เป็น 5.9+ ในอนาคต
  • Node.js 22 LTS EOL: Apr 30, 2027 (~10 เดือน) — ติดตาม; plan migrate ไป Node 24 LTS ใน Q1 2027

การปฏิบัติตาม PDPA (Thai Data Protection Act)

การปกป้องข้อมูลส่วนบุคคล

  • Data residency: ข้อมูลส่วนบุคคลทั้งหมดเก็บในประเทศไทย (ไม่ส่งออกไปยัง cloud)
  • Consent: Admin ตั้งค่า consent สำหรับบันทึกวิดีโอ (banner + audit log)
  • Retention: ลบเหตุการณ์/สแนปช็อตโดยอัตโนมัติตามนโยบาย retention
  • Right to erasure: Admin สามารถลบข้อมูลผู้ใช้ตามคำขอ (ลบ + audit log)
  • Data processing agreement: Template พร้อมสำหรับลูกค้า
  • Breach notification: Audit log จับเก็บการเข้าถึงทั้งหมด + การเปลี่ยนแปลง

ความปลอดภัย Infrastructure

  • Database: PostgreSQL SSL/TLS บังคับ IP whitelist นโยบายรหัสผ่านแข็งแกร่ง
  • API Server: HTTPS เท่านั้น HSTS header CSP policy
  • Environment: Docker rootless mode read-only filesystem ที่เป็นไปได้
  • Secrets: .env ยกเว้นจาก git secrets จัดการผ่าน env vars + Docker secrets
  • Reverse Proxy: Cloudflare Tunnel (optional) + nginx WAF rules
  • Monitoring: Fail2ban (brute-force protection) intrusion detection พร้อม

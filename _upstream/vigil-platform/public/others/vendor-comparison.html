การรับ Snapshot — แต่ละยี่ห้อทำงานอย่างไร

Bosch — 2 วิธีตามลำดับ

1
MQTT Embedded (base64)
payload Appearance.Image = base64 JPEG อยู่ใน MQTT message เลย — ไม่ต้อง pull เพิ่ม · IVA Pro FW 9.x ส่งมาในทุก event ที่มี object detection · บันทึก ก่อน HTTP snap เสมอ
2
HTTP Snapshot Pull (fallback + VCA overlay)
ถ้าไม่มี MQTT base64 → GET http://{ip}/snap.jpg?VCAOverlay=1 (Basic auth) · VCAOverlay=1 ให้กล้อง burn bounding box ไว้บน JPEG · ดึงเฉพาะ event ที่ "เข้า" (ไม่ดึงตอน leave) · ไม่ดึง Aggregation event

Hikvision — 1 วิธีหลัก + Face พิเศษ

1
ISAPI Streaming Channel Picture
GET /ISAPI/Streaming/channels/10{N}/picture (Digest auth, 2-step) · N = snapshot_stream config (default 1 = main stream) · pull หลัง event arrive ทันที
★
Face Capture — multipart synchronization
faceCapture ส่งมา 3 part: JSON event → face crop JPEG → background JPEG · ingester รอ crop + background พร้อมกัน (pending map + 8s timeout) แล้วค่อย INSERT · ได้ทั้ง face crop (gallery) + full frame (modal)

Dahua — 4 ชั้น (ซับซ้อนที่สุด)

1
snapManager event JPEG
/cgi-bin/snapManager.cgi?action=attachFileProc — กล้องส่ง JPEG มาพร้อม event ผ่าน stream คู่ขนาน (Digest auth) · รอ 1,200ms ก่อน fallback
2
RTSP Clip Buffer Frame (burst scoring)
สแกน media-buffer/{cam}/ หา .ts segment รอบ event time → ffmpeg extract หลาย frame → score ด้วย object detection area std + motion diff → เลือก frame ที่ดีที่สุด
3
CGI Live Snapshot (fallback ช้า)
GET /cgi-bin/snapshot.cgi?channel=1 — ดึง live frame ณ เวลาที่ query (ช้ากว่า event เกิดขึ้นจริงแล้ว) · ทำ mark ว่า low_confidence
↑
Clip Resolver (post-hoc upgrade)
หลัง media-recorder บันทึก clip เสร็จ → pg_notify clip_done → dahua-cgi.js รับ → re-score จาก full clip → replace snapshot ถ้าดีกว่า · ช่วย low_confidence / missing snap

สิ่งที่ควรรู้ — ข้อควรระวัง & ลักษณะพิเศษ

Bosch — สิ่งที่ต้องทำฝั่งกล้อง

  • ต้อง configure Bosch camera ให้ publish MQTT ไปที่ EMQX (IP:1883) ด้วย credentials ที่ได้จาก Auto-provision
  • IVA rules ต้องตั้งใน Bosch Configuration Manager (CM) — ถ้าไม่ตั้ง rule = ไม่มี RuleEngine event มา
  • ถ้าไม่ทำ Camera Calibration + Object Calibration ใน CM → ไม่มี object_class / likelihood / speed / GPS ใน event (แต่ event ยังมาปกติ)
  • IVA Pro FW 9.x ส่ง snapshot embed ใน MQTT · FW เก่าอาจไม่มี → ระบบ fallback ไป HTTP pull เอง
  • MotionAlarm ถูก filter ออกโดยตั้งใจ (too noisy) — ไม่บันทึกใน events table

Hikvision — ข้อควรรู้

  • ต้องเปิด Smart Event ใน Hikvision Web GUI ก่อน — ถ้าปิด = alertStream ไม่มี event ส่งมา
  • Firmware บางรุ่นปิด alertStream ไว้ → เปิดได้ที่ Configuration > Network > Advanced Settings > Integration Protocol
  • Digest auth — Hikvision ปฏิเสธ Basic auth โดย default · ingester ทำ 2-step handshake อัตโนมัติ
  • Face Capture ซับซ้อน — ต้องรอทั้ง face crop + background JPEG (8s timeout) ก่อน INSERT · event อาจ delay 1-8s
  • videoloss event ทุก ~10s ใช้เป็น heartbeat อัพเดท last_seen_at — ถ้า alertStream ขาด กล้องจะเป็น offline ใน dashboard
  • Reconnect auto 5s เมื่อ stream หลุด · ไม่ต้อง restart process

Dahua — ข้อควรรู้

  • ต้องเปิด Smart Plan → IVS ใน Dahua Web GUI ก่อน · กำหนด Rule type + zone drawing
  • Face Detection ≠ Face Capture — Dahua Face Detection เป็นแค่ bounding box ระดับ SD ไม่ใช่ face analytics จริง → ระบบตั้งใจไม่รองรับ
  • snapManager อาจไม่รองรับในบาง model/firmware → ingester auto-fallback เป็น RTSP buffer โดยไม่ error
  • Timezone ของ Dahua: data.UTC คือ LOCAL time ส่งมาเป็น unix timestamp → ingester หัก offset ทั้งชั่วโมงออก เพื่อ normalize เป็น server time
  • Clip resolver ทำงาน หลัง clip capture เสร็จ → snapshot ของ event อาจ update ใหม่อีกครั้งหลัง ~10-30s
  • ถ้า ffmpeg ไม่ได้ติดตั้งบน server → RTSP buffer ไม่ทำงาน → ตกไปใช้ CGI live (snap ช้า)

ทั้ง 3 ยี่ห้อ — Pipeline ร่วมกัน

  • ทุก event ผ่าน alert-engine → rule matching, cooldown, quiet hours, LINE notification (Bosch: ผ่าน pg_notify alert_event → alert-worker (PM2 แยก); Hik/Dahua: direct onEvent())
  • pg_notify('new_event', id) → api-server LISTEN → WebSocket broadcast → Dashboard real-time update
  • pg_notify('event_for_clip', ...) → media-recorder ตัดสินใจ capture clip ตาม cameras.enable_clip_capture
  • Snapshot บันทึกไว้ที่ snapshots/ folder · ชื่อไฟล์ = {camera_id}_{event_id}_{timestamp}.jpg
  • Dedup: Bosch ไม่มี (MQTT deliver once), Hikvision/Dahua มี 3s window ต่อ camera+event type
  • กล้องทุกยี่ห้อ update cameras.last_seen_at ทุกครั้งที่รับ message/heartbeat → ใช้ตรวจ online/offline

Config Fields — cameras-config.json

  • ทั่วไป (ทุกยี่ห้อ): camera_id, camera_name, vendor, ip_address, username, password, latitude, longitude, location, notes
  • Bosch เพิ่มเติม: mqtt_username, mqtt_password (auto-provisioned), http_port
  • Hikvision เพิ่มเติม: http_port, snapshot_stream (channel number, default 1)
  • Dahua เพิ่มเติม: http_port, snapshot_path, dahua_transport, dahua_event_snapshot (bool), dahua_snapshot_lookback_ms, dahua_server_frame_offsets_ms (array)
  • Config reload เป็น hot-reload ไม่ต้อง restart process เมื่อแก้ config

Network Planning สำหรับ 50 กล้อง (ตัวอย่าง 2MP)

  • Bosch 50 ตัว: ~0 Mbps idle + burst เมื่อมี event (เล็กน้อย)
  • Hikvision 50 ตัว: ~0 Mbps idle + burst เมื่อมี event (เล็กน้อย)
  • Dahua 50 ตัว (clip on, H.265): ~50 Mbps continuous (50 × ~1 Mbps)
  • แนะนำ: ถ้า network จำกัด ให้ปิด clip capture ใน Dahua หรือใช้ sub-stream RTSP + limit bitrate ที่กล้อง
  • Server disk: clip buffer ใช้ disk ด้วย (~10-20 GB ต่อ 10 กล้อง/ชั่วโมง ที่ H.265 2MP)

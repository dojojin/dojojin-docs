Recipe: เพิ่ม Migration

Schema เก่าวิวัฒน์ผ่าน migration files เท่านั้น — ห้ามแก้ db/init.sql เพื่อ evolve schema (init.sql เป็น fresh install baseline). src/migrate.js รัน migration ทุกไฟล์ก่อน Express listen และ fail-fast ถ้า error (ตั้งใจ — GOTCHAS #19)

ขั้นตอน

1

ตรวจ migration number ล่าสุด:

ls db/db_migration_0*.sql | sort | tail -3

ถ้าล่าสุดคือ 074 → ไฟล์ใหม่ต้องเป็น 075

2

สร้างไฟล์ db/db_migration_075_<topic>.sql — ทุก statement ต้อง idempotent:

-- db_migration_075_<topic>.sql
-- <อธิบาย migration นี้ทำอะไร>

-- เพิ่ม column
ALTER TABLE my_table ADD COLUMN IF NOT EXISTS new_col TEXT;

-- เพิ่ม column พร้อม default
ALTER TABLE my_table ADD COLUMN IF NOT EXISTS flag BOOLEAN DEFAULT FALSE;

-- เพิ่ม index
CREATE INDEX IF NOT EXISTS idx_my_table_new_col ON my_table(new_col);

-- เพิ่ม row (settings, categories, etc.)
INSERT INTO system_settings (key, value, description)
VALUES ('my_key', 'default_value', 'คำอธิบาย')
ON CONFLICT DO NOTHING;

-- สร้าง table ใหม่
CREATE TABLE IF NOT EXISTS new_table (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- เปลี่ยน type หรือ rename column (ต้องระวัง — ใช้ DO block)
DO $$ BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name='my_table' AND column_name='old_col'
  ) THEN
    ALTER TABLE my_table RENAME COLUMN old_col TO new_col;
  END IF;
END $$;
3

อัปเดต db/init.sql ด้วย — เพื่อให้ fresh install ได้ schema เดียวกัน (ใส่ในตำแหน่งที่สมเหตุผล)

ทำไมต้องอัปเดตทั้ง 2 ที่

init.sql รันบน Docker volume ใหม่เท่านั้น — ถ้าไม่อัปเดต fresh install จะไม่มี column ใหม่ แต่ migration จะไม่รันเพราะ DB ไม่มีตารางใน schema_migrations ที่ระบุว่าต้อง skip

4

ทดสอบ: restart api-server แล้วดู log

pm2 restart api-server
pm2 logs api-server --lines 30

ต้องเห็น Migration applied: db_migration_075_<topic>.sql และไม่มี error

Idempotent Pattern ที่ควรรู้

กรณีPattern ที่ใช้
เพิ่ม column ADD COLUMN IF NOT EXISTS
เพิ่ม index CREATE INDEX IF NOT EXISTS
เพิ่ม table CREATE TABLE IF NOT EXISTS
เพิ่ม row INSERT ... ON CONFLICT DO NOTHING
เปลี่ยนชื่อ / type (destructive) DO $$ BEGIN ... IF EXISTS ... END $$;
drop column / drop table DROP COLUMN IF EXISTS / DROP TABLE IF EXISTS

สิ่งที่ migrate.js ทำ

  • อ่านไฟล์ db/db_migration_*.sql เรียงตาม filename
  • ตรวจ schema_migrations table — ถ้ารันแล้วข้าม
  • รัน SQL ทั้งไฟล์แบบ transaction
  • บันทึก filename ลง schema_migrations
  • ถ้า error → process.exit(1) ก่อน Express listen (ตั้งใจ)

ห้ามทำ

  • ห้ามแก้ migration ที่รันไปแล้ว — migration runner ข้ามไฟล์ที่มีใน schema_migrations อยู่แล้ว การแก้ไม่มีผล แต่ทำให้ DB จริงกับ file ไม่ตรงกัน
  • ห้ามเขียน statement ที่ไม่ idempotent — รัน migration ซ้ำต้องไม่ error
  • ห้าม try/catch รอบ migration error — migration ล้มเหลวต้อง abort (STUBBORN_FACT)

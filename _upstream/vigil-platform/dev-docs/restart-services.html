Restart Services — LNP Trap

กับดักที่อันตรายที่สุดใน manual ops — อ่านก่อนแตะ PM2 ทุกครั้ง

ถ้า restart PM2 จาก terminal ผิดประเภท — กล้อง Bosch MQTT ทั้งหมดจะ disconnect และ Local Network access หายไป (EHOSTUNREACH) รีคัฟเวอร์ได้แต่เสียเวลา

กฎเหล็ก: ห้าม Restart จาก

  • Claude Code / Claude shell
  • tmux session
  • SSH terminal จากเครื่องอื่น
  • Terminal ใดก็ตามที่เปิดโดยไม่ใช่ macOS GUI โดยตรง

วิธี Restart ที่ถูกต้อง

ใช้ .command script เสมอ

เปิด Terminal GUI ใหม่ด้วย .command script ที่เตรียมไว้:

# วิธีที่ 1: จาก terminal ที่ถูกต้อง (macOS GUI Terminal)
open -a Terminal /Users/dojojin/vigil-platform/scripts/pm2-lan-safe-restart.command

# วิธีที่ 2: ดับเบิลคลิก .command ใน Finder
scripts/pm2-lan-safe-restart.command

Script นี้เปิด Terminal ใหม่ในบริบท macOS GUI ที่มี Local Network permission — ทำให้ PM2 restart แล้วยังเข้าถึง LAN ได้

ทำไม LNP ถึงเป็นกับดัก (root cause)

macOS Local Network Privacy (LNP) — ทุก process ที่ต้องการเชื่อมต่อ local network ต้องได้รับ permission จาก macOS GUI. PM2 process ที่ถูก spawn จาก terminal ที่ไม่ใช่ GUI จะไม่ได้ permission นี้ → EHOSTUNREACH เมื่อพยายามเชื่อมต่อ EMQX broker

การ brew upgrade node หรือ ffmpeg ก็ทำให้ LNP record หายได้ (GOTCHAS #84)

คำสั่ง PM2 ที่ใช้บ่อย

รันจาก macOS GUI Terminal เท่านั้น:

# ดูสถานะทุก process
pm2 status

# ดู log realtime
pm2 logs api-server --lines 50
pm2 logs alert-worker --lines 30
pm2 logs mqtt-subscriber --lines 30

# Restart service เดียว
pm2 restart api-server
pm2 restart alert-worker

# Restart ทุก process
pm2 restart all

# หยุดทั้งหมด
pm2 stop all

# เริ่มใหม่ทั้งหมด (ใช้ ecosystem.config.js)
pm2 start ecosystem.config.js

ข้อยกเว้นของกฎเหล็ก: pm2 restart <app เดียว>

กฎ "ห้าม restart จาก non-GUI shell" ด้านบนใช้กับ การ (re)start ตัว PM2 daemon เอง เท่านั้น (pm2 kill ตามด้วย pm2 resurrect หรือ pm2 start) — เพราะ grant ของ macOS Local Network Privacy (LNP) ผูกกับ context ของ daemon process (ดู GOTCHAS #84)

pm2 restart <app-name> **ตัวเดียว** เป็นแค่ RPC สั่ง daemon ที่รันอยู่แล้วให้ respawn child process นั้นตัวเดียว — daemon เองไม่ได้ restart เลย ไม่กระทบ grant ที่มีอยู่ — สั่งจาก shell ไหนก็ได้ (SSH, tmux, Claude Code shell) ปลอดภัย ยกเว้น app ที่ restart เป็น process ที่ต้องเชื่อมกล้อง (ffmpeg-based recorder, ingester) ซึ่งควรระวังเป็นพิเศษเพราะ symptom ของ grant หายจะไม่เห็นทันที

ecosystem.config.js's env block เปลี่ยน — ต้องมากกว่าแค่ restart

pm2 kill && pm2 resurrect (LAN-safe restart script ปกติ) ไม่ pick up การเปลี่ยน env block ใน ecosystem.config.js — เพราะ pm2 resurrect อ่านจาก ~/.pm2/dump.pm2 (snapshot จากตอน pm2 save ครั้งก่อน) ไม่ได้ re-read config file เลย (GOTCHAS #115)

# แก้ ecosystem.config.js's env block แล้ว ต้องรันแบบนี้แทน (ยังต้องผ่าน GUI Terminal เพราะเป็นการ start daemon ใหม่)
pm2 start ecosystem.config.js   # apply env ใหม่ให้ process ที่ชื่อตรงกันที่กำลังรันอยู่
pm2 save                        # persist ให้ resurrect รอบถัดไปจำค่านี้ได้

# verify:
pm2 jlist | grep -A2 '"NODE_ENV"'

services.sh — Full Lifecycle

# ใช้ script นี้สำหรับ start/stop เต็มรูปแบบ (ใน GUI Terminal)
bash scripts/services.sh start
bash scripts/services.sh stop
bash scripts/services.sh status

services.sh จัดการ PID lock และ singleton pattern ด้วย — ป้องกัน orphan process (GOTCHAS: ห้ามใช้ pkill หรือ node x.js &)

ถ้า LNP หายไปแล้ว (EHOSTUNREACH)

1

ตรวจสอบว่า error เป็น EHOSTUNREACH จริง:

pm2 logs mqtt-subscriber --lines 20
2

ไป System Preferences → Privacy & Security → Local Network — ตรวจว่า Terminal.app มี checkmark

3

Restart ด้วย pm2-lan-safe-restart.command จาก macOS GUI (ดูวิธีด้านบน)

4

ถ้ายังไม่หาย — อาจต้อง reboot Mac แล้ว restart services ใหม่จาก GUI Terminal

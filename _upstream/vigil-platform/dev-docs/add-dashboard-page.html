Recipe: เพิ่ม Dashboard Page / Widget

Dashboard เป็น Vanilla JS SPA — ไม่มี build step, ไม่มี framework เปิดไฟล์แก้ได้เลย ไม่ต้อง compile

STUBBORN_FACT

ห้าม import React / Vue / Svelte / Material Web Components — Vanilla JS เป็นการตัดสินใจถาวร (DECISIONS.md #1)

ทำไม S5 ถึงแยก dashboard.js → 21 page files (MAINT-FE-001)

  • อ่านได้ทันที — ไฟล์ 80–1,500 ลบ. เห็น context เต็มในหน้าเดียว vs dashboard.js เดิม ~10,500 ลบ.
  • AI context ใช้งานจริง — โหลดเฉพาะ page-cameras.js เมื่อแก้กล้อง ไม่กิน context ของส่วนอื่น
  • หาเจ้าของโค้ดชัดขึ้น — "หน้า Stats มีปัญหา" → เปิด page-stats.js ได้เลย
  • browser dev cache — แก้ page-events.js → browser invalidate แค่ไฟล์นั้น ไม่ทั้ง 10k บรรทัด
  • แก้ไม่กระทบส่วนอื่น — แก้ executive summary ไม่มีทางพลาดแตะ nav bindings หรือ health check
  • Runtime / bundle size ไม่เปลี่ยน — classic <script> multi-file บน HTTP/2 แทบไม่ต่าง; globals ยังแชร์ผ่าน window เหมือนเดิม

เพิ่ม Page ใหม่

1

เพิ่ม nav item ใน sidebar HTML ใน dashboard/index.html:

<a data-page="my-feature" data-i18n="nav.myFeature"></a>
2

เพิ่ม i18n key — ดู Recipe: เพิ่ม i18n String

// dashboard/i18n.js
th: { 'nav.myFeature': 'ฟีเจอร์ของฉัน', 'page.myFeature': 'หน้า Feature' }
en: { 'nav.myFeature': 'My Feature',     'page.myFeature': 'Feature Page' }
3

สร้างไฟล์ใหม่ dashboard/page-my-feature.js (พร้อม copyright header) แล้วเพิ่ม render function:

// ============================================================
// Vigil Platform — My Feature Page
// @author    Prakasit Rochanavipart (Dojo-mAn)
// @copyright (c) 2025-2026 Prakasit Rochanavipart. All Rights Reserved.
// @license   Proprietary
// ============================================================

async function renderMyFeature() {
  const container = document.getElementById('page-my-feature');
  if (!container) return;
  container.innerHTML = '<p style="color:var(--dim)">กำลังโหลด...</p>';

  try {
    const res = await fetch(`${API}/api/my-feature`, {
      headers: { Authorization: `Bearer ${_token}` }
    });
    const data = await res.json();
    container.innerHTML = buildMyFeatureHTML(data);
  } catch (e) {
    container.innerHTML = `<p style="color:var(--status-bad)">โหลดไม่สำเร็จ: ${e.message}</p>`;
  }
}

function buildMyFeatureHTML(data) {
  // Build HTML string — use template literals
  return `
    <h2 style="color:var(--text-primary)">${I18N.t('page.myFeature')}</h2>
    <table>...</table>
  `;
}
4

เพิ่ม container ใน dashboard/index.html และ hook ใน page switch handler:

<div id="page-my-feature" class="page" style="display:none"></div>

เพิ่ม <script> tag ใน index.html ก่อน dashboard.js:

<script src="/page-my-feature.js"></script>
<script src="/dashboard.js"></script>

ค้น case 'appearances': (หรือ page ที่ใกล้เคียง) ใน page switch logic (page-nav-bindings.js) แล้วเพิ่ม:

case 'my-feature':
  renderMyFeature();
  break;

SVG Icons

Icons อยู่ใน dashboard/icons.svg เป็น sprite — ใช้ <use>:

<svg class="icon" width="16" height="16" viewBox="0 0 24 24">
  <use href="icons.svg#eye"></use>
</svg>

ดู symbol IDs ที่มีอยู่: grep 'id="' dashboard/icons.svg

ห้ามใช้ emoji เป็น UI icon

ใช้ SVG sprite (currentColor) — ไม่ใช่ emoji และไม่ใช้ icon webfont. Health Report PNG ที่ render ผ่าน SVG+sharp จะ abort ถ้ามี emoji (GOTCHAS #25a)

Responsive — ≤768px บังคับ

ก่อน commit UI ทุกครั้ง — ทดสอบใน DevTools ที่ขนาด ≤768px เสมอ:

  • ใช้ CSS Grid grid-template-columns: repeat(auto-fill, minmax(Xpx, 1fr)) แทน fixed columns
  • Grid children ที่มี content กว้าง — ต้องใส่ min-width: 0 (GOTCHAS #29)
  • Table บน mobile — อาจต้องใส่ overflow-x: auto ใน wrapper
  • ห้าม hardcode width เป็น px กว้าง — ใช้ % หรือ fr

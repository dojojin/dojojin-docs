# Design: Group 1 — i18n Dedicated Pass

**Date:** 2026-06-16
**Scope:** Migrate hardcoded Thai/English dynamic strings in `dashboard/page-*.js` into `dashboard/i18n.js`
**Approach:** File-by-file sequential (A) — commit per file, reproduce per commit

---

## Goal

All user-visible dynamic strings generated by JavaScript (empty states, error messages, labels, placeholders, option text) must go through `I18N.t()` so Thai↔English switch works completely.

**Not in scope:**
- `_APP_GENDER / _APP_COLORS / _APP_BAGS / _APP_SLEEVES` in `page-snapshots.js` — already have `{th, en}` local struct; leave as-is
- Static HTML strings using `data-i18n` attributes — already handled
- Comments, vendor strings, i18n.js dictionary content itself
- LINE alert text (carve-out per project policy)

---

## Scan Method

Before touching any file, run:

```bash
rg -n "innerHTML\s*[+=].*'[^']*[ก-๙][^']*'|\
textContent\s*=\s*'[^']*[ก-๙][^']*'|\
alert\('|\.innerHTML\s*=\s*\`[^']*[ก-๙]" \
dashboard/page-*.js --no-heading
```

And for hardcoded English dynamic strings:

```bash
rg -n "'(All|No |Error|Loading|Saving|Save|Cancel|Connected|Disconnected|Success|Failed|Warning|Confirm|Delete|Add|Edit|Send)[^']*'" \
dashboard/page-*.js --no-heading | grep -v "//\|I18N\|i18n\|_APP_"
```

Produce ranked list → fix highest-hit files first.

---

## Namespace Map

Add keys under these namespaces in `dashboard/i18n.js`:

| Namespace | Use |
|---|---|
| `common.*` | All, Loading, Error, Save, Cancel, shared labels |
| `cam.*` | Camera status, config messages |
| `snap.*` | Snapshot empty/filter/error states |
| `alert.*` | Alert rule dynamic messages |
| `ar.*` | Appearance recognition UI labels (non-`_APP_*`) |
| `usr.*` | User management messages |
| `sys.*` | System page messages |
| `map.*` | Map settings messages |
| `cat.*` | Categories page messages |

Rule: every new key must have both `th` **and** `en` entries before committing.

---

## Migration Pattern

### JS string in template literal

```js
// before
el.innerHTML = `<div class="empty">ไม่พบข้อมูล</div>`;

// after
el.innerHTML = `<div class="empty">${I18N.t('common.noData')}</div>`;
```

### textContent assignment

```js
// before
el.textContent = 'Loading...';

// after
el.textContent = I18N.t('common.loading');
```

### alert / toast

```js
// before
alert('บันทึกสำเร็จ');

// after
alert(I18N.t('common.saveSuccess'));
```

### option text

```js
// before
`<option value="">${I18N.t('common.all')}</option>` // already correct pattern
`<option value="">ทั้งหมด</option>`                 // needs migration

// after
`<option value="">${I18N.t('common.all')}</option>`
```

**i18n strings used in `innerHTML` do NOT need `escapeHtml()`** — they come from a controlled internal dictionary, not from DB/API/user input.

---

## Execution Order

Fix from highest actionable hit count to lowest. Per-file commit:

```
fix(i18n): localize page-alerts dynamic strings
fix(i18n): localize page-user-mgmt dynamic strings
fix(i18n): localize page-appearance dynamic strings
fix(i18n): localize page-snapshots UI strings
fix(i18n): localize page-system / page-cameras / remaining pages
```

`dashboard/i18n.js` is committed together with each page file it modifies (one commit per page+i18n pair).

---

## Reproduce

After each file commit:

```bash
node --check dashboard/i18n.js
node --check dashboard/page-<name>.js
```

Manual (each touched page):
1. Open dashboard → navigate to the page
2. Switch Thai → English → Thai using language toggle
3. Trigger dynamic states: empty list, loading, error, filter reset
4. Verify all visible strings follow the selected language
5. Check no `undefined` or raw key strings appear

---

## What Not To Do

- Do not move `_APP_GENDER/_APP_COLORS/_APP_BAGS/_APP_SLEEVES` into i18n.js
- Do not add keys without both `th` and `en`
- Do not use i18n string as a fallback source-of-truth (both languages must be real translations)
- Do not sweep static HTML — only JS-generated strings
- Do not batch multiple pages into one commit (makes reproduce harder to isolate)

คู่มือการเชื่อมต่อ Partner API

1ภาพรวม

  • เป็น REST API ผ่าน HTTPS รับส่งข้อมูลแบบ JSON ทุกคำขอขึ้นต้นด้วย /v1
  • ทุกคำขอต้องลงลายเซ็น ด้วย App Key และ App Secret ของท่าน (HMAC-SHA256) ไม่ใช้รหัสผ่านหรือ token ที่หมดอายุเป็นรอบ
  • ข้อมูลที่ท่านได้รับกำหนดตามข้อตกลง ระหว่างท่านกับเรา ทั้งชุดข้อมูล ฟิลด์ พื้นที่ และช่วงเวลาย้อนหลัง
  • เวลาในข้อมูลเป็นมาตรฐาน ISO 8601 (UTC) เว้นแต่เอกสาร OpenAPI ของท่านระบุว่าเป็นวันตามเวลาประเทศไทย

2สิ่งที่ท่านจะได้รับ

รายการรายละเอียด
โดเมนสำหรับเชื่อมต่อที่อยู่ HTTPS ที่ใช้เรียก API (ระบุในข้อตกลง)
App Keyรหัสประจำตัวของระบบท่าน ส่งไปกับทุกคำขอ
App Secretกุญแจลับสำหรับลงลายเซ็น ส่งให้แยกช่องทางกับ App Key และแสดงเพียงครั้งเดียว
วันหมดอายุของสิทธิ์หลังวันนี้คำขอจะถูกปฏิเสธ ต่ออายุได้โดยติดต่อผู้ประสานงาน
ชุดตัวอย่างโค้ดตัวอย่างที่ใช้งานได้จริง vigil_client.py (Python 3.8+) และ vigil-client.mjs (Node 18+) ไม่ต้องติดตั้งไลบรารีเพิ่ม

3เริ่มต้นใน 5 ขั้น

  1. เก็บ App Secret ให้ปลอดภัย ไว้ในตัวแปรสภาพแวดล้อมหรือระบบเก็บความลับ ห้ามเขียนลงในโค้ด บันทึก log หรือแนบในอีเมล
  2. ตั้งนาฬิกาเครื่องให้ตรง (NTP) เวลาในคำขอต้องคลาดจากเวลาของเราไม่เกิน 5 นาที
  3. เรียก GET /v1/healthz ถ้าได้ 200 แปลว่าลายเซ็นถูกต้องและสิทธิ์ของท่านพร้อมใช้งาน
  4. เรียก GET /v1/openapi.json เพื่อดูสัญญาของท่าน ได้แก่ endpoint ฟิลด์ ชนิดข้อมูล และพารามิเตอร์ที่ท่านได้รับจริง
  5. เริ่มดึงข้อมูล ตามหัวข้อที่ 5 หรือใช้ชุดตัวอย่าง ซึ่งจะอ่านเอกสารของท่านแล้วดึงทุก feed ในช่วงหนึ่งชั่วโมงล่าสุดให้ดู
export VIGIL_BASE=https://<โดเมนที่ได้รับ>
export VIGIL_KEY=<App Key>
export VIGIL_SECRET=<App Secret>
python3 vigil_client.py        # หรือ  node vigil-client.mjs
เอกสาร OpenAPI ของท่านคือข้อมูลอ้างอิงหลักระบบสร้างเอกสารนี้จากสิทธิ์ที่ท่านได้รับจริงทุกครั้งที่เรียก จึงไม่มีวันอธิบายสิ่งที่ท่านเรียกไม่ได้ เมื่อผู้ประสานงานแจ้งการเปลี่ยนแปลงสิทธิ์ ให้อ่านเอกสารนี้ใหม่

4การลงลายเซ็นคำขอ

ทุกคำขอต้องมี header ต่อไปนี้

Headerค่า
X-Ca-KeyApp Key ของท่าน
X-Ca-NonceUUID ใหม่ทุกคำขอ ห้ามใช้ซ้ำ (คำขอที่ใช้ซ้ำจะถูกปฏิเสธ)
X-Ca-Timestampเวลาปัจจุบันเป็นมิลลิวินาทีนับจาก epoch

สำหรับคำขอ POST ที่มี body ให้ใส่ค่า Content-MD5 เป็นบรรทัดที่สาม ระหว่าง application/json สองบรรทัด

4 ข้อที่พลาดบ่อยที่สุด 1) path ต้องรวม /v1 ด้วย · 2) พารามิเตอร์เรียงตามชื่อ และใส่ค่าแบบไม่ encode ในข้อความที่ลงลายเซ็น (แต่ใน URL จริงต้อง encode ตามปกติ) · 3) ไม่มี body = ไม่มีบรรทัด Content-MD5 เลย ไม่ใช่บรรทัดว่าง · 4) ค่าพารามิเตอร์ใน query ต้องเป็น ASCII เท่านั้น ข้อความภาษาไทยให้ส่งใน body ของคำขอ POST

ตัวอย่าง (Python)

import base64, hashlib, hmac, time, uuid

def sign(method, path, query, body, key, secret):
    md5 = base64.b64encode(hashlib.md5(body).digest()).decode() if body else ""
    nonce, ts = str(uuid.uuid4()), str(int(time.time() * 1000))
    signed_path = path + ("?" + "&".join(f"{k}={query[k]}" for k in sorted(query)) if query else "")
    lines = [method, "application/json"] + ([md5] if md5 else []) + ["application/json"]
    text = "\n".join(lines) + "\n" + \
           f"x-ca-key:{key}\nx-ca-nonce:{nonce}\nx-ca-timestamp:{ts}\n" + signed_path
    sig = base64.b64encode(hmac.new(secret.encode(), text.encode(), hashlib.sha256).digest()).decode()
    headers = {"Accept": "application/json", "Content-Type": "application/json",
               "X-Ca-Key": key, "X-Ca-Nonce": nonce, "X-Ca-Timestamp": ts, "X-Ca-Signature": sig,
               "X-Ca-Signature-Headers": "x-ca-key,x-ca-nonce,x-ca-timestamp"}
    if md5:
        headers["Content-MD5"] = md5
    return headers

โค้ดฉบับเต็มที่ส่งคำขอ เดินหน้าข้อมูล และจัดการข้อผิดพลาดแล้ว อยู่ในชุดตัวอย่างที่ท่านได้รับ

5การดึงข้อมูลต่อเนื่อง

คำตอบของ endpoint ที่เป็นรายการมีรูปแบบเดียวกัน

{
  "data": [ ... ],
  "nextCursor": "eyJ2IjoxLCJ0Ijoi...",
  "pageSize": 500
}
  • since จุดเริ่มต้นของช่วงเวลา (ISO 8601) until จุดสิ้นสุด (ไม่รวมตัวมันเอง ไม่ระบุก็ได้)
  • pageSize จำนวนแถวต่อหน้า 1–1,000 (ค่าเริ่มต้น 100)
  • nextCursor ส่งกลับมาเป็นพารามิเตอร์ cursor เพื่อขอหน้าถัดไป จนกว่าจะได้ค่า null

การติดตามข้อมูลใหม่แบบต่อเนื่อง

  1. ครั้งแรก เรียกด้วย since ที่ต้องการ แล้วเดินตาม nextCursor จนหมด
  2. เก็บ nextCursor ตัวสุดท้ายที่ได้รับไว้ (ถ้าหน้าสุดท้ายได้ null ให้เก็บตัวก่อนหน้า)
  3. รอบถัดไปเรียกต่อจาก cursor ที่เก็บไว้ อย่าคำนวณ since ใหม่เอง เพราะจะได้ข้อมูลซ้ำทุกรอบ
  4. ช่วงห่างที่แนะนำคือทุก 10–60 วินาที ตามความต้องการของท่าน
ข้อมูลประเภทยอดสรุปอาจถูกปรับภายหลังถ้ารายการของท่านมีฟิลด์ updated_at แปลว่าตัวเลขของช่วงเวลาล่าสุดอาจถูกปรับปรุงในภายหลัง (โดยปกติภายในวันถัดไป) ให้ดึงช่วงนั้นซ้ำและแทนที่ข้อมูลเดิมเมื่อ updated_at ใหม่กว่าที่ท่านมี
ค่าศูนย์ไม่ได้แปลว่าไม่มีเหตุการณ์เสมอไปอุปกรณ์บางจุดตรวจจับบางเหตุการณ์ไม่ได้ ก่อนสรุปจากค่าศูนย์หรือค่า false ให้อ่านคำอธิบายของฟิลด์นั้นในเอกสาร OpenAPI ของท่าน

7ข้อผิดพลาด

ข้อผิดพลาดตอบกลับในรูปแบบ RFC 7807 เช่น

{ "type": "https://<โดเมน>/v1/errors/bad-signature",
  "title": "bad-signature", "status": 401,
  "detail": "Signature did not match. Verify the string-to-sign layout and the secret." }
สถานะtitleความหมาย / วิธีแก้
400invalid-parameterพารามิเตอร์ไม่ถูกต้อง อ่านรายละเอียดใน detail
400since-too-oldขอข้อมูลเก่ากว่าที่มี detail บอกวันเก่าสุดที่ดึงได้
400non-ascii-query · repeated-query-paramquery มีอักขระที่ไม่ใช่ ASCII หรือพารามิเตอร์ซ้ำ ข้อความภาษาไทยให้ส่งใน body
401missing-headers · bad-signatureตรวจ header และวิธีลงลายเซ็นตามหัวข้อที่ 4
401stale-timestamp · nonce-replayตั้งนาฬิกาเครื่องให้ตรง และใช้ X-Ca-Nonce ใหม่ทุกคำขอ
401unknown-key · inactive · expiredApp Key ไม่ถูกต้อง ถูกระงับ หรือหมดอายุ ติดต่อผู้ประสานงาน
403not-permittedข้อมูลนั้นไม่อยู่ในข้อตกลงของท่าน
404not-foundไม่มี endpoint นี้ ตรวจกับเอกสาร OpenAPI ของท่าน
429rate-limitedเกินเพดานจำนวนคำขอ รอตาม Retry-After แล้วขอใหม่
503query-too-slowคำขอกว้างเกินไป แคบช่วงเวลาลง
คำแนะนำในการเขียนโปรแกรมสถานะ 4xx (ยกเว้น 429) ไม่ควรลองใหม่ซ้ำทันที เพราะผลจะเหมือนเดิมจนกว่าจะแก้ต้นเหตุ ส่วน 429 และ 503 ให้รอแล้วลองใหม่ หรือแคบช่วงเวลาลง

8ความเข้ากันได้

ภายใน /v1 เราอาจ เพิ่มฟิลด์ในคำตอบ เพิ่มพารามิเตอร์ที่ไม่บังคับ และเพิ่ม endpoint ใหม่ โปรแกรมของท่านจึงต้องไม่ล้มเมื่อพบฟิลด์ที่ไม่รู้จัก

ภายใน /v1 เราจะไม่ ลบหรือเปลี่ยนชื่อฟิลด์ เปลี่ยนชนิดหรือความหมายของฟิลด์ ทำให้พารามิเตอร์ที่ไม่บังคับกลายเป็นบังคับ หรือเปลี่ยนวิธีลงลายเซ็น การเปลี่ยนแปลงเหล่านี้จะมาเป็น /v2 โดยเปิด /v1 ไว้ใช้ควบคู่ตามระยะเวลาที่แจ้งล่วงหน้า

สิ่งเดียวที่อาจเปลี่ยนเฉพาะท่านคือสิทธิ์ตามข้อตกลง ฟิลด์ที่ไม่อยู่ในสิทธิ์จะไม่ปรากฏในข้อมูล ซึ่งจะสะท้อนในเอกสาร OpenAPI ของท่านทันที

9ความปลอดภัยและข้อมูลส่วนบุคคล

  • ใช้ข้อมูลตามวัตถุประสงค์ที่ระบุในข้อตกลงเท่านั้น และปฏิบัติตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
  • App Key และ App Secret ใช้ได้เฉพาะระบบของท่าน ห้ามเปิดเผยหรือส่งต่อ
  • หากสงสัยว่า App Secret รั่วไหล แจ้งผู้ประสานงานทันที เพื่อออกกุญแจชุดใหม่ ชุดเดิมจะใช้ไม่ได้ทันที
  • เราบันทึกการเข้าถึงทุกครั้ง (เวลา ระบบที่เรียก ผลลัพธ์ และที่อยู่ IP) เพื่อความปลอดภัยและการตรวจสอบ
  • เก็บข้อมูลที่ได้รับไว้ไม่นานเกินความจำเป็น และลบเมื่อหมดวัตถุประสงค์หรือเมื่อข้อตกลงสิ้นสุด

10การขอข้อมูลเพิ่มเติม

หากท่านต้องการข้อมูลเพิ่มจากที่ได้รับ กรุณาติดต่อผู้ประสานงานตามข้อตกลง พร้อมระบุ

  • วัตถุประสงค์และกรณีใช้งาน (สิ่งที่ต้องการทำ ไม่ใช่รายชื่อฟิลด์)
  • ความถี่และช่วงเวลาที่ต้องการ
  • ฐานทางกฎหมายในการใช้ข้อมูล หากเกี่ยวข้องกับข้อมูลส่วนบุคคล

เราจะพิจารณาและกำหนดชุดข้อมูลขั้นต่ำที่เหมาะกับกรณีใช้งานของท่าน เมื่ออนุมัติแล้ว สิทธิ์ใหม่จะปรากฏในเอกสาร OpenAPI ของท่านโดยอัตโนมัติ

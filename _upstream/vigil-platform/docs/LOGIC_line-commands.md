## 1. หลักคิดเดียวที่ทั้งฟีเจอร์ยึด

> **คำสั่งใน LINE = ยิง endpoint เดิมของระบบ ในนามของผู้ใช้จริงคนหนึ่ง**

ผู้สั่งแต่ละคนผูกกับบัญชีในระบบหนึ่งบัญชี ตอนประมวลผล: สร้าง session อายุ 60 วินาที →
ยิง loopback `http://127.0.0.1:<API_PORT>` → ลบ session ทิ้งใน `finally`

ได้อะไรมาฟรีทันที: **ขอบเขตไซต์ · สิทธิ์ระดับหน้า (viewGuard) · การกันเขียนของ auditor ·
audit_log** — และตัวเลขตรงกับหน้าจอเสมอเพราะเป็นคิวรีตัวเดียวกันจริง ๆ ไม่ใช่คิวรีคู่ขนาน
ที่ค่อย ๆ เพี้ยนออกจากกัน

**ทางที่ไม่เลือก:** ใช้ `X-Internal-Token` ยิงตรง — token นั้นข้ามการตรวจสิทธิ์ทั้งหมด
ผลลัพธ์จะไม่ถูกจำกัดตามไซต์ของผู้สั่ง = ข้อมูลข้ามเขตหลุดเข้ากลุ่ม LINE

**สิ่งที่ต้องรู้:** session ชั่วคราวโผล่ใน Settings › Sessions ชั่วครู่ ปั๊ม
`user_agent = 'line-command'` ไว้ให้แยกออกว่าไม่ใช่คนล็อกอิน

## 3. ประตูที่ผู้สั่งต้องผ่าน

| ชั้น | ไม่ผ่านแล้วเป็นยังไง |
|---|---|
| LINE ส่ง `source.userId` มา | (ยืนยันแล้วว่ากลุ่มส่งมาให้ — log 2026-09-08 19:01) |
| มีแถวใน `line_operators` และ `enabled` | **เงียบสนิท** ไม่ตอบอะไรเลย · ลงปูมเป็น `denied` |
| แถวนั้นผูกกับบัญชีที่ยัง `enabled` | เงียบเหมือนกัน — บัญชีถูกลบ/ปิด = ใช้ไม่ได้ทันที ไม่ใช่กลายเป็นไม่จำกัดสิทธิ์ |
| ห้องอยู่ใน `allow_in` (ว่าง = ทุกห้อง) | เงียบ + ลงปูม |

**ทำไมต้องเงียบ ไม่ตอบว่า "ไม่มีสิทธิ์":** การตอบคือการบอกใบ้ว่าระบบนี้มีอยู่ และในกลุ่ม
มีคนพิมพ์คุยกันตลอด การตอบทุกข้อความคือการก่อกวน

**แชทกลุ่ม/ห้อง ต้อง @ บอทก่อนถึงจะเข้าทางคำสั่ง** (decision #289, 2026-09-16 — กลับคำ
ตัดสินเดิมของ 2026-09-08 ที่ไม่บังคับ @) เจอซ้ำเป็นรอบที่ 3 ว่าผู้สั่งคุยเรื่องอื่นล้วน ๆ
ในกลุ่มแล้วบอทเด้งการ์ด "ยังไม่เข้าใจคำสั่งนี้" ใส่ — เนื้อหาคุยคนละเรื่องทุกครั้งจนไล่แก้
ทีละคำสั่งด้วย "คำที่ต้องมีครบ"/"คำต้องห้าม" ไม่ทัน เช็คจาก `message.mention.mentionees[].isSelf`
ของ LINE จริง (ยืนยันบน prod 2026-09-15) ไม่ต้องเดาชื่อบอท
**แชท 1:1 กับบอทยังไม่ต้อง @** เหมือนเดิม เพราะไม่มีทางเข้าใจผิดว่าใครเป็นคนฟัง

## 4. การจับคำสั่ง

1. **ปรับข้อความ** เลขไทย→อารบิก · ตัดคำสุภาพ **รายคำ** (`\b` ใช้กับอักษรไทยไม่ได้ — ดู GOTCHAS #198 หมายเหตุ)
2. **ให้คะแนน** คำเรียกที่เจอ ให้คะแนนตามความยาว (คำยาวชนะคำสั้น: "หมวกนิรภัย" ชนะ "หมวก")
   · `require_all` ไม่ครบ = ตัดทิ้ง · เจอคำใน `exclude` = ตัดทิ้ง
   · **`require_all` เป็นตัวจำกัด ไม่ใช่ตัวเรียก** — ไม่มี trigger ตรงสักคำต้องได้ 0
3. **ดึงค่าจากประโยค** ช่วงเวลา · จำนวน · ไซต์ · กล้อง · ป้ายทะเบียน · จำนวนชั่วโมง
4. **ตัดสิน** อันดับ 1 ต้องนำอันดับ 2 เกิน 30% ไม่งั้นถามกลับ
5. **ไม่เจอเลย** = เงียบ เว้นแต่มีคำซ้อนกับคำเรียกจริง ๆ ค่อยเสนอ 3 คำสั่งใกล้เคียง

### ช่วงเวลาภาษาไทย (`helpers/thaiPeriod.js`)
"ชั่วโมงที่แล้ว" = **ชั่วโมงเต็มก่อนหน้า** (ถามตอน 15:20 ⇒ 14:00-14:59) ไม่ใช่ 60 นาทีล่าสุด ·
วันนี้ · เมื่อวาน · N วัน · สัปดาห์/เดือน · "12 ชั่วโมงที่ผ่านมา" (เวลาวิ่งจริง) ·
วันที่ระบุ (พ.ศ. แปลงให้) · เขตเวลา Asia/Bangkok ตายตัว

**การ์ดต้องพิมพ์ช่วงเวลา/ขอบเขตที่ตีความได้กลับไปเสมอ** ไม่งั้นคนอ่านไม่มีทางรู้ว่าเลขนี้
ตอบคำถามของเขาจริงหรือเปล่า

## 5. ขอบเขตของคำตอบ

- **กล้องชนะไซต์เสมอ** (แคบกว่า = สิ่งที่เขาถาม) · คนละไซต์กับที่พิมพ์มา = เขียนกำกับบนการ์ด
- **ถามทั้งไซต์ = ส่งเฉพาะกล้องที่บัญชีนั้นเห็นจริง** และการ์ดเขียนว่า "4 จาก 86 กล้อง"
  ไม่งั้นคนอ่านนึกว่าเป็นยอดทั้งไซต์
- ระบุกล้องที่อยู่นอกสิทธิ์ = **บอกตรง ๆ** ไม่ใช่เงียบแล้วตอบขอบเขตอื่น
- คำสั่งที่ไม่ได้เปิดช่องกล้อง แต่ผู้ใช้ระบุกล้องมา = บอกว่ายังทำไม่ได้ ดีกว่าตอบยอดทั้งไซต์
  ให้คำถามที่ถามถึงกล้องเดียว

การส่ง `cameras=` **ไม่ใช่การให้สิทธิ์** — endpoint ยังใส่ `siteWhere(allowedSites)` ทับเสมอ
ผลลัพธ์คือส่วนร่วมของสองอย่าง

ไซต์เดียวกันนับรถได้จากสองแหล่งที่ไม่เกี่ยวกันเลย — RMUTR-V มีทั้ง Bosch 5100i (นับเส้น

⇒ ทุกการ์ดที่นับรถพิมพ์ที่มาไว้ท้าย (`SENSOR_LPR` / `SENSOR_VCA` ใน `line-answer-sources.js`)
ไม่งั้นคนอ่านเห็นสองเลขแล้วสรุปว่าระบบนับผิด (GOTCHAS #199)

`category_counts` ยัง **บังคับระบุไซต์** (migration 212) เพราะหมวดตั้งแยกตามไซต์คนละเรื่อง
(rmutr-v = รถเข้า/ออก · vss = คนเดินเข้าห้องน้ำ) รวมข้ามไซต์ในใบเดียวไม่ตอบคำถามใครเลย ·
บัญชีที่เห็นไซต์เดียวระบบเติมให้เอง ไม่ถามคำถามที่มีคำตอบเดียว

**เจาะจงหมวดเดียวได้** (migration 213) — ต่อท้ายด้วยชื่อหมวดของไซต์นั้น การ์ดจะเหลือหมวดเดียว
ตัวเลขใหญ่กลายเป็นของหมวดนั้น และใช้ที่ในตารางแจงเข้า/ออกแทนการซ้ำชื่อหมวด · ตัวจับอยู่ใน
`lineCommandRun` **หลังรู้ไซต์แล้ว** เพราะชื่อหมวดอยู่ใน DB และตั้งต่างกันทุกไซต์
(`extractSlots` เป็นฟังก์ชันบริสุทธิ์ ไม่แตะ DB โดยตั้งใจ) · จับแบบ **ชื่อที่ยาวที่สุดที่อยู่ในประโยค**
เพราะชื่อสั้นเป็นส่วนหนึ่งของชื่อยาวได้ · พิมพ์ "เฉพาะ …" มาแล้วจับไม่ได้ = **ตอบว่ามีหมวดอะไรบ้าง**
ไม่ใช่เงียบแล้วส่งยอดรวมซึ่งหน้าตาเหมือนคำตอบที่ถูกต้องทุกประการ

### ภาพผลค้นหาที่ส่งเข้า LINE — `kind='seek'` (เจ้าของสั่งเปิด 2026-09-09)

ภาพของ AcuSeek ไม่ใช่ไฟล์บนดิสก์ แต่เป็น URL ภายในของเครื่องค้น
(`http://10.0.10.12:6120/isapiHikStor?...&token=...`) ⇒ ส่งผ่าน `/pub/img/` ไม่ได้
(อ่านจาก SNAPSHOT_DIR) และ `/api/acuseek/picture` ก็ไม่ได้ (ต้องมี session ส่วน LINE
เป็นคนมาดึงภาพเอง) · เส้นใหม่คือ `GET /pub/seek/:blob` ใน `routes/acuseek.js`

ด่านที่วางไว้ — ทดสอบยิงจริงครบทุกช่องแล้ว (2026-09-09):

| ยิงแบบ | ได้ |
|---|---|
| ลิงก์จริง (ไม่มี session เหมือน LINE) | 200 · image/jpeg 52 KB |
| ไม่มีลายเซ็น / ลายเซ็นผิด | 403 |
| แก้ก้อนที่ปิดผนึกหนึ่งตัวอักษร | 403 |
| ยืดวันหมดอายุเอง | 403 |
| ลิงก์หมดอายุ | 410 |

- **ปิดผนึกด้วย AES-256-GCM ไม่ใช่ base64** (`sealUrl`/`openUrl` ใน `helpers/signedImage.js`)
  เพราะ URL ต้นทางมี `token=` ของเครื่องเก็บภาพ และข้อความ LINE ค้างอยู่ในเครื่องของทุกคนในห้อง
- **เปิดผนึกแล้วยังต้องผ่าน `PIC_RE` ซ้ำ** — กัน SSRF ถ้ากุญแจหลุด · edge ตรวจอีกชั้นเหมือนเดิม
- ลิงก์ถูก mint **ตอนตอบคำสั่งในนามผู้ใช้จริง** เท่านั้น (ผ่านการตรวจสิทธิ์กล้องมาแล้ว)
  และอายุตาม `signed_image_expire_hours` ⇒ โมเดลความเสี่ยงเท่ากับ `/pub/img/` ที่ใช้ส่งภาพ
  แจ้งเตือนอยู่ทุกวัน · เพิ่ม prefix ใน `PUBLIC_PREFIXES` (`api-server.js`) พร้อมเหตุผล

### รอบ "ครอบคลุมหรือยัง" (2026-09-09) — A/B/C/D

เจ้าของยกประโยคที่คนพิมพ์จริงมา 5 ประโยค **ตกทั้งหมด** และหนึ่งในนั้นตอบผิดแบบดูเหมือนถูก
(ได้ยอดอ่านป้ายของทุกไซต์ ตอบคำถามที่ถามถึงรถจักรยานยนต์ของกล้องเดียว) ⇒ แก้เป็น 4 กลุ่ม

**A — ปิดของที่ผิดอยู่**
- `ก่อนเที่ยง` เคยให้ 12:00-13:00 เท่ากับ `หลังเที่ยง` (ลอกช่วง "พักเที่ยง" มาใช้ผิดความหมาย)
- `10.30` เดี่ยว ๆ ไม่ถูกอ่านเป็นเวลา ⇒ ตอบทั้งวันเงียบ ๆ
- ไม่ระบุไซต์ = การ์ดไม่เขียนขอบเขตเลย · ระบุไซต์กับคำสั่งที่ไม่รับไซต์ = ถูกทิ้งเงียบ
- ชื่อกล้องบางส่วนไม่ติด (`ท่าฉัตรไชย` ทั้งที่มีกล้องชื่อนั้น 6 ตัว)
  ⚠️ ตัวจับชื่อบางส่วนต้องอ่านเฉพาะคำ **หลังคำว่า "กล้อง"** และตัดชื่อไซต์ทิ้ง ไม่งั้น
  "กล้องดับกี่ตัว ภูเก็ต" จะเอา "ภูเก็ต" ไปตรงกับ "สนามบินภูเก็ต (C44)"

**B — พิมพ์แบบคนพูด**
- ภาษาไทยไม่มีช่องว่าง ⇒ การตัด "คำฟุ่มเฟือย" รายคำ **ไม่ช่วยเลย** กับ "สรุปจำนวนป้ายทะเบียน"
  ซึ่งเป็นคำเดียว · และการใส่ "รายงาน" ลงรายการคำฟุ่มเฟือยทำให้คำสั่งที่ใช้คำนั้นเป็นคำเรียก
  จับไม่ได้เลย ⇒ ทางที่ได้ผลคือเพิ่ม **คำเรียกที่เป็นคำนามจริง** (includes() รับคำนำหน้าอยู่แล้ว)
- 🔴 ห้ามใส่คำเรียกกว้าง ๆ ("ป้ายทะเบียน") ให้คำสั่งนับยอด — ยาว 11 ตัวจะชนะ
  "ขอรูป"+"รูปรถ" (10) แล้วดึงคำถามเรื่องรูปไปนับยอดแทน
- คำสั่งใหม่ `object_counts` — นับตามชนิดวัตถุจากกล้องวิเคราะห์ภาพ · ยอดมาจาก header
  `X-Total-Count` ซึ่งมีเพดาน 10,000 ⇒ ชนเพดานต้องเขียน "+" และบอกให้แคบขอบเขต

**C — กลุ่มกล้อง** — `ทั้งหมด/ทุกตัว` ต่อท้ายชื่อบางส่วน = รวมทุกตัวในกลุ่ม ·
ลำดับขอบเขต: กล้องเดียว → กลุ่มกล้อง → ไซต์

**D — สถานะกล้องบน HCP** — `/api/hcp/devices` (`status` 1=online 2=offline 0=unknown)
· **คนละชุดกับ `camera_offline` โดยตั้งใจ**: ตัวนั้นนับจาก event ที่ไหลเข้าระบบเรา ตัวนี้คือ
สิ่งที่ HCP มองเห็น รวมกล้องที่ HCP ดูแลตัวเดียว (ของจริง 13 ดับ จาก 758) — สองเลขไม่ควรเท่ากัน
⇒ การ์ดเขียนที่มา + อายุข้อมูลเสมอ · admin เท่านั้น และภูเก็ตที่เดียว
· คำว่า "สถานะกล้อง" เป็นคำเรียกของทั้งสองคำสั่ง ⇒ กัน `hcp` ออกจาก `camera_offline`
ไม่งั้นคะแนนสูสีแล้วบอทถามกลับทุกครั้ง

### จังหวัดของป้ายทะเบียน (2026-09-09)

`สรุปจำนวนป้ายทะเบียน จังหวัด ยะลา ที่หาดใหญ่ เมื่อวาน` เคยได้ยอดรวมของหาดใหญ่ทั้งหมด

- ระบุจังหวัดมา = สลับไปนับที่ `/api/lpr?count=only&region=…` (คอลัมน์ `license_plates.region`

  พร้อมข้อความให้ตรวจชื่อ ดีกว่ามีรายชื่อที่ต้องตามอัปเดตตลอด
- คำสั่งอื่นที่ยังกรองจังหวัดไม่ได้ **ต้องบอก** เมื่อเจอคำว่า "จังหวัด" ในประโยค ไม่ใช่ตอบ
  ขอบเขตอื่นเงียบ ๆ (บทเรียนซ้ำรอบที่สามในรอบเดียวกัน — ดูกลุ่ม A)

## 7. สูตรสำหรับผู้ดูแล

**เพิ่มผู้สั่งคนใหม่** — ให้เขาพิมพ์อะไรก็ได้ในกลุ่มที่บอทอยู่หนึ่งครั้ง → Settings ›

(**แนะนำสร้าง viewer เฉพาะกิจ** กำหนดไซต์/กล้องตามที่ควรเห็น ไม่ใช่ผูกกับ admin)

**บอทจับคำสั่งผิด / ไม่จับ** — ดูแท็บ "บันทึกการใช้งาน" แถวที่ขึ้น "จับไม่ได้" คือประโยคที่
ยังไม่มีคำเรียกรองรับ · แก้ที่คำเรียก/คำที่ต้องมีครบ/คำที่ห้ามมี ในหน้าเดียวกัน

**คำสั่งสองตัวชนกัน** — ใส่คำที่ต่างกันลงใน "คำที่ต้องมีครบ" ของตัวหนึ่ง และ "คำที่ห้ามมี"
ของอีกตัว (ของจริง: "จำนวนรถแยกประเภท" ชนกับ "ยอดอ่านป้ายทะเบียน" → migration 210)

**อยากรู้ว่าป้ายนี้เงียบเพราะอะไร**
```sql
SELECT * FROM lpr_plate_mutes WHERE plate_number = '1กอ88';
-- และดู alert_logs.status: plate_muted (ถาวร) · plate_muted_until (ชั่วคราว) ·
--                          group_muted · channel_disabled · cooldown_skip
```

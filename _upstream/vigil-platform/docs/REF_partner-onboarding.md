# เปิด account ให้ 3rd party — ทีละขั้น

> สร้าง 2026-08-07 · ใช้กับ **HTTP API `https://meta.dojojin.tech/v1/`** เท่านั้น
> ทางเก่า (ต่อ Postgres ตรง) ดู [`REF_third-party-integration.md`](REF_third-party-integration.md) §3
> เหตุผลเบื้องหลัง → [`SPEC_partner-api_2026-08-07.md`](SPEC_partner-api_2026-08-07.md)

**ใช้เวลาจริงประมาณ 10 นาที** ถ้าตอบข้อ 1 ได้แล้ว

## ขั้น 1 — ตอบ 5 คำถามก่อนพิมพ์คำสั่งใด ๆ

เขียนคำตอบลงกระดาษก่อน เพราะทุกข้อกลายเป็นค่าที่ต้องใส่ และแก้ทีหลังบางข้อยุ่งกว่า

| # | คำถาม | ตัวเลือก | ใส่ที่ไหน |
|---|---|---|---|
| 1 | **ชื่อย่อ (slug)** | ตัวพิมพ์เล็ก a-z 0-9 _ · ห้ามเว้นวรรค · **กลายเป็นชื่อ database role แก้ไม่ได้** | `create <slug>` |
| 2 | **เห็นไซต์ไหนบ้าง** | เลือกจากรายการที่หน้าจอดึงมาจากฐานข้อมูลเอง · ไม่ระบุ = ทุกไซต์ | ฟอร์ม / `--sites` |
| 3 | **อายุสัญญากี่วัน** | 30 · 60 · 90 · 120 · 180 · 365 · ไม่ระบุ = ไม่หมดอายุ | `--days` |
| 4 | **ให้ข้อมูลอะไรบ้าง** | ค่าเริ่มต้น = ทุก view · จำกัดได้ทีหลังบนหน้าจอ | ขั้น 3 |
| 5 | **ย้อนหลังได้กี่วัน** | ไม่ระบุ = ตาม retention ของระบบ | ขั้น 3 |

> 🔴 **ข้อ 4 มีข้อควรระวังทางกฎหมาย** — `v_license_plates_public` (ป้ายทะเบียน) ถูกจัดเป็นข้อมูลส่วนบุคคล
> ต้องมีการอนุญาตจากเจ้าของข้อมูลก่อน (ดู §7 ของ `REF_third-party-integration.md`)
> **ยังไม่พร้อม → ปิดไว้ก่อน เปิดทีหลังคลิกเดียว** ไม่ต้องรอทุกอย่างพร้อมพร้อมกัน

## ขั้น 2 — สร้าง account

### วิธี ก · จากหน้าจอ (แนะนำ)

**ตั้งค่า → เชื่อมต่อภายนอก → ปุ่ม `+ สร้าง partner`**

กรอก slug · ชื่อที่แสดง · ไซต์ · ย้อนหลัง · โควตา · อายุ · บันทึก → กด **สร้าง**
→ **key และ secret แสดงทันทีบนหน้าจอ พร้อมปุ่มคัดลอก** (ซ่อนเองใน 30 วินาที · กดแสดงใหม่ได้ทุกเมื่อ)

### วิธี ข · จาก CLI

บนเครื่อง **vigilcentral** (ไม่ใช่ edge):

```bash
cd ~/vigil-platform
set -a; . ./src/.env; set +a

node src/partner-admin.js create cib "CIB" --sites hkt --days 90
```

**ผลลัพธ์**

```
  created role cib_ro

  partner "cib" created.

  App Key:    vk_xxxxxxxxxxxxxxxxxxxxxxxx
  App Secret: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
  Expires:    2026-11-05 (90 days left)
```

### App Secret อ่านคืนได้ — แต่ทุกครั้งถูกบันทึก

เก็บแบบเข้ารหัส AES-256-GCM (**ถอดได้ เพราะ HMAC ต้องใช้ค่าจริงคำนวณซ้ำทุก request**)

**ลืมแล้วดูใหม่ได้** — หน้าจอกดปุ่ม `แสดง` หรือ `node src/partner-admin.js reveal <slug>`
· ทุกครั้งที่กดจะมี audit ว่า **ใครดู เมื่อไหร่ ของ partner ไหน**
· ไม่ต้อง `rotate` เพราะลืม — `rotate` ไว้ใช้ตอน secret รั่วจริงเท่านั้น

**สิ่งที่คำสั่งนี้ทำให้อัตโนมัติ**
- สร้าง Postgres role `cib_ro` แล้ว `GRANT third_party_readonly`
- เก็บ secret แบบ AES-256-GCM
- ตั้งวันหมดอายุ

## ขั้น 3 — จำกัดสิทธิ์ (ถ้าต้องการ)

**Dashboard → ตั้งค่า → เชื่อมต่อภายนอก** (admin เท่านั้น)

1. เลือก partner ในคอลัมน์ซ้าย
2. แท็บ **ฟิลด์ที่เห็นได้** — ติ๊กเปิด/ปิดรายคอลัมน์ หรือกด `ทั้งหมด` / `ไม่เอา` ต่อ view
3. กด **ใช้สิทธิ์นี้**

**ยังไม่มีผลจนกว่าจะกดยืนยัน** — ติ๊กแล้วขึ้นแถบเตือนและทำเครื่องหมายช่องที่ต่างจากของจริง

> ⚠️ **ครั้งแรกที่แก้สิทธิ์ผ่านหน้านี้ partner จะออกจาก role กลาง `third_party_readonly` ถาวร**
> และหน้านี้เป็นเจ้าของสิทธิ์ของเขาตั้งแต่นั้น · เป็นข้อจำกัดของ Postgres เอง (membership ชนะ column revoke)

**จำนวนวันย้อนหลัง · โควตา · ชื่อ · ไซต์ · บันทึก** — กดปุ่ม **`แก้ไข`** ที่การ์ดของ partner
(เดิมต้องเขียน SQL เอง · ตอนนี้ไม่ต้องแล้ว)

> **ถ้า partner ต้อง backfill ครั้งแรก** — โควตา default 60/นาที เผื่อการใช้งานปกติ 118 เท่า — 1 วัน ≈ 12 นาที · 7 วัน ≈ 85 นาที ที่โควตา default
> ตั้งสูงชั่วคราวแล้วลดกลับหลังเขา sync ทัน

## ขั้น 4 — ส่งให้ partner

**ส่ง 4 อย่างนี้** (secret ผ่านช่องทางที่ส่งรหัสผ่านได้ — ไม่ใช่แชททั่วไป):

| | |
|---|---|
| Base URL | `https://meta.dojojin.tech` |
| App Key | `vk_...` |
| App Secret | ช่องทางแยก |
| เอกสาร | `GET /v1/openapi.json` — **generate จากสิทธิ์ของเขาเอง** ไม่ต้องเขียนเอกสารให้ |
| ตัวอย่างโค้ด | [`partner-samples/vigil_client.py`](partner-samples/vigil_client.py) — ทดสอบกับ API จริงแล้ว |

**บอกเขา 4 ข้อนี้ด้วย** — เป็นจุดที่ integrator พลาดบ่อยที่สุด:

1. **เซ็น path เต็มรวม `/v1`** — `/v1/cameras` ไม่ใช่ `/cameras`
2. **nonce ใหม่ทุก request** · **นาฬิกาต้องตรง ±5 นาที** (คลาดกว่านั้นได้ `401 stale-timestamp` ไม่ใช่ `bad-signature`)
3. **ค่า query ต้องเป็น ASCII** — ป้ายทะเบียนไทยต้องส่งทาง `POST /v1/lpr/search` ใน body เท่านั้น
4. **เดินต่อด้วย `nextCursor` ที่ได้มา** อย่าคำนวณ `since` ใหม่ทุกรอบ ไม่งั้นจะดึงหางซ้ำทุกครั้ง

## ขั้น 5 — ให้ partner ทดสอบ

```bash
GET https://meta.dojojin.tech/v1/healthz
```

**200 = พิสูจน์พร้อมกัน 2 อย่าง** — เซ็นถูก และ database role ใช้งานได้จริง

| ได้ | แปลว่า |
|---|---|
| `200` | ผ่าน |
| `401 bad-signature` | ลายเซ็นไม่ตรง — เช็คว่าเซ็น path เต็มรวม `/v1` ไหม |
| `401 stale-timestamp` | นาฬิกาเครื่องเขาคลาด |
| `401 nonce-replay` | ใช้ nonce ซ้ำ |
| `401 expired` | เลยวันหมดอายุ → `extend` |
| `401 unknown-key` / `inactive` | key ผิด หรือถูกถอนแล้ว |
| `403 not-permitted` | ยังไม่ได้ให้สิทธิ์คอลัมน์ที่ endpoint นั้นต้องใช้ |
| `404` | ยิงผิด path — โฮสต์นี้เสิร์ฟเฉพาะ `/v1/*` |

## ขั้น 6 — ตรวจจากฝั่งเรา

**ตั้งค่า → เชื่อมต่อภายนอก** ดูว่า:

- **เรียกล่าสุด** เปลี่ยนจาก "ยังไม่เคย" แล้ว
- **เรียก 7 วัน (สำเร็จ/ล้ม)** — ถ้าล้มเยอะแปลว่าเขายังเซ็นไม่ถูก ช่วยดูให้
- **ฟิลด์ที่เห็นได้** ตรงกับที่ตกลงกันไว้

## นโยบายความเข้ากันได้ของ `/v1` — บอก partner ตั้งแต่วันแรก

> เขียนไว้ 2026-08-08 ตอนที่ยังไม่มี partner สักราย — **ช่วงเดียวที่ประกาศกฎแล้วบังคับตัวเองได้
> โดยไม่ต้องเจรจากับใคร** · เหตุผลเต็ม → `SPEC_partner-api_2026-08-07.md` §7 Phase CP

| ทำได้ใน `v1` | ต้องขึ้น `/v2` |
|---|---|
| เพิ่ม field ใน response | ลบ / เปลี่ยนชื่อ field |
| เพิ่ม query/body param ที่เป็น **optional** | เปลี่ยนชนิดข้อมูล หรือความหมาย |
| เพิ่ม endpoint ใหม่ | เปลี่ยน param จาก optional เป็นบังคับ |
| | **เปลี่ยนสูตร string-to-sign** |

**ข้อที่ต้องบอก partner ให้ชัดที่สุด:** *"client ต้องไม่พังเมื่อเจอ field ที่ไม่รู้จัก"* —
ถ้าไม่บอก การเพิ่ม field ก็กลายเป็น breaking change ทันที และกติกาข้างบนคุ้มครองไม่ได้

**ทำไมต้องมี** — 2026-08-08 แก้สูตรลายเซ็นไป **3 commit ในวันเดียว** (`06c9861` `3c6b2f8`
กับ `vigil_client.py`) ฟรีทั้งหมดเพราะยังไม่มี partner · ถ้ามีอยู่แล้วทั้งสามครั้งจะทำให้เขา
พังเงียบ ๆ ด้วยอาการ `bad-signature` ตลอดกาล ซึ่งเป็นอาการที่หาสาเหตุยากที่สุด

### 2 อย่างที่ผูกกับ partner รายนั้น ไม่ใช่กับเวอร์ชัน

- **ถอนสิทธิ์คอลัมน์ = breaking เฉพาะราย** — ติ๊กเอาคอลัมน์เดียวออกแล้ว endpoint นั้น
  **ตอบ `403` ทั้งเส้น ไม่ใช่แค่ field หาย** (query เป็นรายการคอลัมน์ตายตัว → Postgres `42501`)
  ⇒ ต้องแจ้ง partner ก่อน ไม่ใช่ติ๊กแล้วจบ
- **`nextCursor` เป็นของเรา** — partner ต้องมองเป็นข้อความทึบ **ห้ามแกะ** และให้เดินต่อจาก
  ค่าที่เราคืนเสมอ ห้ามประกอบขึ้นเอง

## ดูแลต่อเนื่อง

**จากหน้าจอ** — เลือก partner แล้วใช้ปุ่มด้านบน: `แก้ไข` · `ต่ออายุ` · `ออก key ใหม่` · `ถอนสิทธิ์` / `เปิดใช้อีกครั้ง`

**จาก CLI** (ทำอย่างเดียวกัน เรียกฟังก์ชันเดียวกัน)

```bash
node src/partner-admin.js list                       # ดูทั้งหมด + วันหมดอายุ
node src/partner-admin.js extend cib --days 90       # ต่ออายุ (นับจากวันนี้)
node src/partner-admin.js rotate cib                 # secret รั่ว — key เดิมตายทันที อายุไม่ถูกรีเซ็ต
node src/partner-admin.js revoke cib                 # ปิดทันที คำขอถัดไปได้ 401
node src/partner-admin.js reveal cib                 # อ่าน key/secret ที่เก็บไว้
```

**หน้าจอเตือนเองเมื่อเหลือ ≤14 วัน** · **"หมดอายุแล้ว" ชนะ "ใช้งาน"** บนการ์ด เพราะแถวยัง active แต่ credential ใช้ไม่ได้

**ควรดูเป็นระยะ**
- partner ที่ `เรียกล่าสุด: ยังไม่เคย` = สิทธิ์ที่แจกแล้วไม่มีใครใช้ → ถอน
- `key ที่ไม่รู้จักพยายามเข้า` = มีคนลอง key ที่ไม่มีอยู่ (partner ที่กำลัง debug ก็ทำให้ขึ้นได้)
- `role หาย` = คำขอของ partner รายนั้นล้มทุกครั้ง

node src/partner-admin.js revoke cib
